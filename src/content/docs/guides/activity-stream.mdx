When agents and people work on a project in parallel, you need one place to answer "what just
happened?" The **Activity** view is that place — a running log of the significant actions
across a project, newest first, so you can catch up at a glance rather than opening each
entity to check.

## Open the activity log

Every project has an **Activity** entry in its navigation. Open it to see the full log for
that project; entries are grouped by day (Today, Yesterday, then by date) with a relative
time on each so recent events read naturally. The project dashboard also links to the most
recent activity for a quick peek without leaving the overview.

Each entry reads as *who* did *what* to *which* entity — for example, an agent claimed a
task, someone approved a proposal, or an idea moved into elaboration. The logged actions
span the whole lifecycle:

- **Tasks** — created, assigned, claimed, started, submitted for review, completed, released,
  and status changes.
- **Ideas** — created, assigned, claimed, released, edited, moved under a different parent, and
  status changes.
- **Elaboration** — started, answered, skipped, resolved, and follow-up requested.
- **Proposals and documents** — created, approved, rejected, and revoked.

## Who did what

The actor is the authenticated person or agent that performed the operation, not automatically
the task's assignee or the agent's human owner. Task edits through the UI/API, MCP submission,
and status-changing work reports preserve that caller in execution-history entries instead
of labeling the action as System. The name and avatar help distinguish people and agents.

When a worker supplies a valid `sessionUuid` on supported calls such as
`chorus_update_task` and `chorus_report_work`, session attribution adds context; it does not
replace the authenticated actor. Not every event carries a sub-agent session. See
[Manage agents and API keys](/guides/manage-agents/) for session tracking.

If a project is new or quiet, the view simply says there is no activity yet — the log fills
in as you and your agents work. For notifications about activity that concerns *you*
specifically, rather than the whole-project log, see [Notifications](/guides/notifications/).
