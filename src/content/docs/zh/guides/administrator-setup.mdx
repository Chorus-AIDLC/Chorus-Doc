当你负责管理 Chorus，而运行智能体的机器由另一个人运维时，请参照本指南操作。如果你要连接的是自己的机器，使用应用内的**设置向导**通常更快。

## 创建凭据

1. 打开**设置**，进入**智能体**。
2. 选择**创建 API 密钥**。
3. 输入一个能识别该智能体及其负责人或所在机器的名称。
4. 选择与智能体要做的工作最接近的预设。
5. 逐项检查权限，去掉智能体用不到的部分。
6. 创建密钥并立即保存。

如果智能体负责实现类工作，请从**开发者**预设开始。只有当分配给它的工作流确实需要时，才追加提案、文档、项目或管理方面的权限。

## 管理本地工作区用户

在本地认证工作区中，使用已设置密码且处于活跃状态的本地**工作区管理员**账号打开侧边栏中**设置**下方的**工作区用户**。普通用户、OIDC 用户、Default Auth 用户和智能体均不能使用此管理入口。智能体的管理员权限预设不等于工作区管理员角色。超级管理员负责创建工作区及初始管理员，不通过此页面管理日常用户。

1. 选择**邀请用户**，填写用户名和邮箱，显示名称可选。仅在需要时授予工作区管理员角色。
2. 用户名为 3–64 个 ASCII 字母、数字、点、下划线或连字符，须以字母或数字开头且不含 `@`。用户名和邮箱会去除首尾空白并转为小写，仅在当前工作区内唯一，不要求整个部署唯一。
3. 复制结果中的邀请链接，通过私密渠道分享。链接仅在签发时显示，24 小时后过期，且只能使用一次。系统不会自动发送邀请邮件。
4. 受邀用户自行设置密码，然后单独登录。不能通过修改状态来激活尚未设置密码的邀请。

用户列表区分**已邀请**、**活跃**和**已禁用**账号。你可以编辑用户名、邮箱及名称，授予或撤销工作区管理员角色，禁用、重新启用或移除用户，重新签发邀请，或为活跃用户签发密码重置链接。重新启用从未设置密码的账号会恢复为已邀请状态，并返回新邀请。

账号编辑会使该用户的现有会话和旧邀请、重置链接失效；重新签发邀请或重置链接也会使会话及旧链接失效。若操作返回受邀账号的新链接，请重新分享。完成密码重置后，用户须重新登录。密码重置会保留用户的智能体密钥，但禁用或移除密钥所有者后，这些密钥将无法认证。

Chorus 会阻止移除、禁用或降级最后一位有效工作区管理员；尚未接受的邀请不能算作已激活的替代管理员。移除后，历史署名和归属仍保留在原身份上。复用其用户名或邮箱会创建全新身份，不继承旧工作、权限、会话或智能体密钥。

工作区创建及初始管理员恢复见[认证配置](/zh/guides/authentication-setup/)。用户可在[账号设置](/zh/guides/account-and-workspace/)中修改自己的显示名称和头像。

## 向运维人员提供所需信息

通过经批准的安全渠道发送以下信息：

- Chorus 网址；
- 智能体名称和 API 密钥；
- 选定的平台，例如 Claude Code、Codex 或 Kiro；
- 允许智能体工作的目录；
- 你授予的权限。

不要把真实的 API 密钥放进工单、聊天群、截图、shell 命令或源代码仓库。

## 确认访问

请运维人员按照[连接智能体运行环境](/zh/guides/operator-onboarding/)完成配置。完成后：

1. 打开**设置 → 智能体**。
2. 找到该智能体，打开它的连接详情。
3. 确认其状态为**在线**。
4. 确认运行后端、主机和工作目录与预期的机器一致。

如果连接没有上线，请参阅[排查智能体连接故障](/zh/guides/troubleshooting/)。不再使用的凭据应及时撤销，尤其是在更换机器或运维人员之后。
