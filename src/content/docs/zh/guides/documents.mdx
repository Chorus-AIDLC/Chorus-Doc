**文档**是一个项目的书面产物，包括 PRD、规格、设计、笔记以及总结报告。大多数文档在你批准提案时自动生成，但你也可以手动创建。本页讲述文档列表、创建与编辑文档、版本历史、报告如何出现，以及如何删除文档。

## 浏览文档列表

在项目侧边栏选择**文档**，即可看到项目的文档以卡片网格呈现，每张卡片显示标题、类型和版本。一排筛选标签让你按类型收窄列表，包括 **PRD**、**技术规格**、**设计文档**、**笔记**、**总结报告**和**其他**，不属于这些类型的文档会归入**其他**。如需手动添加文档，请使用**新文档**。

## 手动创建文档

选择**新文档**，填写标题和类型，也可以附加一个 Markdown 文件（`.md`、`.txt` 或 `.markdown`）作为初始内容。不带文件创建时，会得到一份空文档，你可以在它的页面里填写。

## 阅读与编辑文档

打开一份文档即可阅读其内容。选择**编辑**修改内容，用**保存更改**保存，每次保存都会推进版本。侧边栏显示文档的详情、它的**来源提案**（设置了来源时带链接指向该提案）以及**版本历史**。正文下方的评论区可用于讨论。

## 文档开头的元数据

如果 Markdown 正文以受支持的 YAML frontmatter 开头，Chorus 会在正文上方用元数据卡片显示这些字段。例如：

```markdown
---
title: CSV 导出
status: draft
---

## 需求
用户可以导出当前结果集。
```

使用扁平的 `key: value` 字段，第一行必须是 `---`，以 `---` 或 `...` 结束。块内允许空行和 `#` 注释。
这不是完整的 YAML 支持，不支持嵌套对象、列表和多行值。无法识别该块时，Chorus 会按原始 Markdown 渲染。

卡片只改变显示方式，不会改变文档类型、工作流状态、存储的正文或导出内容。[Spec-lite](/zh/guides/spec-lite-mode/)
用 frontmatter 将每份变更文档关联到提案和持久文档。

## 文档与报告如何出现在这里

文档以两种方式进入这个列表：

- **来自批准的提案。** 当你批准一份提案时，它的每个文档草稿都会转为一份真实的文档出现在这里；批准会创建什么见[审核提案](/zh/guides/review-a-proposal/)。
- **手动创建。** 上面的**新文档**对话框。

**总结报告**是一种文档类型。这类文档和其他文档一样出现在列表里，可用**总结报告**标签筛选；此外，总结报告还会按想法汇总：在一个想法的**概览**中可以集中阅读它的所有报告，了解该想法的成果。

## 删除文档

用户或超级管理员可以用**删除**按钮删除文档。删除不可恢复，确认前请核对要删除的文档是否正确。
