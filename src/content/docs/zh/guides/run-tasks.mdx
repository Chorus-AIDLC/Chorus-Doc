你批准提案之后，提案里的工作就以真正的**任务**形式存在了。本阶段要做的是把每个任务交给某个人（或某个智能体）去做、按依赖顺序推进，并观察状态前进。本页讲述如何认领和指派任务、读懂依赖图，以及从**开放**到**待验证**的状态路径。

## 打开任务看板

在项目侧边栏选择**任务**。视图切换可在以下几种之间切换：

- **看板**：一块有四列的看板：**待办**、**进行中**、**待验证**和**已完成**。每列显示数量和预估总工时。**待办**列同时容纳**开放**和**已分配**的任务；指派任务只会改变它的状态标记，卡片不会移出待办列。
- **DAG**：依赖图（见下文）。
- **列表**：带状态筛选的紧凑列表，在小屏幕上很好用。

每张卡片会显示任务状态、以小时计的预估、负责人（未指派时显示**分配**链接）、当前有多少个工作者正在处理，以及以“通过数 / 总数”表示的验收标准进度。

## 认领或指派任务

刚落地的任务从**开放**且未分配开始。打开任务查看它的详情面板，然后使用**分配**操作。你可以：

- **分配给我自己**：把任务接过来；你名下的所有开发智能体随后都能看到并处理它。
- **分配给其他用户**：交给一位队友。
- **分配给特定智能体**：指定一个智能体，并可选定它运行所在的工作目录（主机和实例）。
- **释放（清除负责人）**：把任务退回公共池。

指派会把任务从**开放**推进到**已分配**。

## 读懂依赖图

任务很少孤立存在。切换到 **DAG** 视图，把它们看成一张依赖图：每个节点是一个任务，每条箭头从一个任务指向依赖它的任务。布局会自动计算，因此你可以自上而下地读出执行顺序。你也可以在两个节点之间画一条连线来添加依赖。

只有当一个任务所**依赖于**的每个任务都到达**已完成**后，它才能开始。在看板上，被阻塞的任务会显示“依赖未完成”提示；在其上游任务完成之前尝试移动它，会提示你先解除依赖。任务面板会同时列出**依赖于**和**被此任务阻塞**，方便你从两个方向追踪这条链。

## 跟随状态路径

任务会走过一段固定的顺序。你可以在看板各列之间拖动卡片，负责人也可以在任务面板里推进状态：

<div class="table-scroll" role="region" aria-label="任务状态路径" tabindex="0">

  | 状态 | 含义 | 什么让它前进 |
  | --- | --- | --- |
  | 开放 | 从提案落地而来，尚未被接手。 | 有人认领，或你指派它。 |
  | 已分配 | 已有归属，但还没开工。 | 负责人开始工作（要求所有依赖已完成）。 |
  | 进行中 | 正在被处理。 | 负责人提交它以待验证。 |
  | 待验证 | 工作已完成，等待你验证。 | 你验证它，见[验证与完成](/zh/guides/verify-and-complete/)。 |
  | 已完成 | 已验证并接受。 | 没有后续，此时它可能会解锁下游任务。 |

</div>

只有到达**已完成**才会解锁下游任务；停在**待验证**的任务不会。这就是为什么及时验证能让整张图持续流动。

:::note[智能体在做什么]
一旦任务指派给某个智能体且其依赖都已满足，智能体就会认领它、把它移到**进行中**、动手完成工作、附上带证据的工作报告，并提交到**待验证**。你观察状态和报告；开发由智能体完成。关于智能体如何连接、如何在你的项目上运行工作，请参阅[智能体平台参考](/zh/reference/agents/)。
:::

## 下一步

当任务到达**待验证**时，继续阅读[验证与完成](/zh/guides/verify-and-complete/)，去核对它的验收标准并接受工作。
