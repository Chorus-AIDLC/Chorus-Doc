当智能体的做法不对、无限期等待，或需要补充指示时，可以使用这些控制操作。它们作用于已有的对话；要创建新对话，请参阅[从 Chorus 发起远程工作](/zh/guides/remote-control/)。

## 中断正在执行的工作

1. 打开正在运行的对话。
2. 查看最新输出，确认确实需要中断。
3. 选择**打断**。
4. 等待对话报告执行已停止。

打断会先请求智能体进程正常停止。如果它没有在配置的超时时间内停止，后台服务会结束该进程。

:::caution[打断不会撤销已完成的工作]
在打断之前已经完成的文件修改、命令、评论和外部操作都会保留。再次执行之前，请先检查这部分结果。
:::

## 对话一直显示运行中

进程已经结束、对话却仍显示**运行中**时，请在该对话中选择**打断**。即使没有列出活跃执行，
此操作也可用。如果 Chorus 没有可停止的活跃执行，它可以直接把该轮次标记为已中断；
否则会把请求转发给后台服务，并等待停止结果。

轮次结束的上报遇到临时故障时，Chorus 会重试；智能体进程一旦退出，Chorus 就视其为已结束，
即使它启动的某个后台进程仍在运行。这些机制都不限制一个轮次可以运行多久，但运行后端自身的限制仍然适用：
DeepSeek Harness（`dsh`）每轮默认限时 30 分钟，可通过 `CHORUS_DSH_TIMEOUT_MS` 配置。
恢复之前，请检查最后的输出以及仍在运行的进程。

## 检查已完成的部分

恢复之前：

- 阅读智能体最后的输出和错误详情；
- 检查已修改的文件和仍在运行的进程；
- 决定是继续、给出更正后的指令，还是按你平常的版本控制流程丢弃这部分修改。

在弄清第一个会话改动了什么之前，不要在同一目录上再开启第二个会话。

## 恢复对话

当对话已被打断，或在崩溃后可以恢复时：

1. 如果原来的后台服务连接已离线，先把它恢复。
2. 打开同一个对话。
3. 补充更正或缺失的上下文。
4. 选择**恢复**。

恢复会使用原来的智能体连接和工作目录，不会把会话迁移到另一台机器或另一个目录。如果原来的运行环境无法恢复，请明确地开启一个新会话，并带上上一次尝试的相关上下文。

反复失败时，请参阅[排查智能体连接故障](/zh/guides/troubleshooting/)。

## 从终端接管会话

除了界面上的**恢复**按钮，你也可以在自己的终端里继续这个对话。打开对话，在对话记录顶部选择**复制 session ID**。它复制的是智能体 CLI 自己恢复会话时使用的会话 ID，因此手动恢复会回到同一个对话，而不是新开一个。

{/* Screenshot surface: 对话记录顶部的复制 session ID 控件。 */}

在对话原本运行的工作目录下，把复制的会话 ID 传给对应运行后端的恢复命令：

- **Claude Code**：`claude --resume <sessionId>`
- **Codex**：`codex exec resume <thread_id>`
- **Kiro**：`kiro-cli chat --resume-id <sessionId>`

每种运行后端都有自己的 ID 格式，复制到的值就是该后端所接受的形式。各平台的确切命令见对应参考页：[Claude Code](/zh/reference/agents/claude-code/)、[Codex](/zh/reference/agents/codex/) 和 [Kiro](/zh/reference/agents/kiro/)。

Chorus 对每个想法只保留一个会话。如果你从另一个工作目录对该想法开始工作，Chorus 会把这一个会话移到那里，而不是新开一个会话，因此无论它最后在哪里运行，需要接管的始终只有一个对话。完整模型见[在线智能体总览](/zh/guides/online-agents-overview/)。
