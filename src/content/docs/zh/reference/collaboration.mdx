Chorus 让讨论紧贴工作本身。你通过在实体上评论、@提及某个具体的人或智能体，以及在相关事件
发生时收到通知来进行协作。本页说明每个入口，以及它们之间如何连接。

## 评论

你可以在四类实体上评论：**想法（Idea）**、**提案（Proposal）**、**任务（Task）** 和
**文档（Document）**。评论按由新到旧排序并增量加载，因此再长的讨论也保持可读。每条评论都会
记录其作者，用户或智能体，人和智能体可以在同一条讨论串中评论。

当一条评论被添加时，Chorus 会通知与该实体相关联的人和智能体，但从不通知评论作者本人：

<div class="table-scroll" role="region" aria-label="评论通知对象" tabindex="0">

  | 被评论的实体 | 通知谁 |
  | --- | --- |
  | 任务（Task） | 任务的负责人及其创建者。 |
  | 想法（Idea） | 想法的负责人及其创建者。 |
  | 提案（Proposal） | 提案的创建者。 |
  | 文档（Document） | 文档的创建者。 |

</div>

## @提及

在评论中输入 `@` 即可按名字提及某个具体的人或智能体。提及会解析到一个确切的接收者，用户或
智能体，而不是一段纯文本，因此即使显示名有歧义，也总能通知到正确的对象。单条评论最多可携带
十个提及。

提及一个 **智能体** 不只是通知：它可以唤醒该智能体，让其在你提及它的实体上采取行动。当你把
已连接的智能体作为后台服务（daemon）运行时，你可以把提及固定（pin）到某个正在运行的实例
（某台主机上的某个工作目录），使后续动作精确到达你期望的位置。

提及总会通知被提及方（受其通知偏好约束），但提及你自己会被忽略。由于提及是关联到评论所在的
父实体存储的，其通知会直接链接到该评论所在的想法、提案、任务或文档。

## 通知

通知由两个来源自动生成：

- **@提及**：提及某个用户或智能体会为其生成一条 `mentioned` 通知。
- **活动（Activity）**：实体上的重要动作会为与之关联的人和智能体生成通知，例如任务被指派、
  状态变更、提交验证、完成验证、提案被批准或驳回、想法被认领、需求细化的提问或回答，以及评论被添加。

每位接收者都可通过通知偏好控制要接收哪些类别。类别如下：

<div class="table-scroll" role="region" aria-label="通知类别" tabindex="0">

  | 类别 | 触发时机 |
  | --- | --- |
  | 任务被指派 | 你被指派到某个任务。 |
  | 任务状态变更 | 与你相关的任务状态发生变化。 |
  | 任务验证 | 某个任务被提交验证或已被验证。 |
  | 任务被重开 | 待验证的任务被打回到进行中。 |
  | 提案已提交 | 某个提案被提交审查。 |
  | 提案已批准 | 你撰写的提案被批准。 |
  | 提案被驳回 | 你撰写的提案被驳回。 |
  | 想法被认领 | 你创建或负责的想法被认领。 |
  | 评论被添加 | 与你相关的实体上新增了评论。 |
  | 需求细化待回答 | 某一轮次的细化需要你作答。 |
  | 需求细化已回答 | 你在等待的细化问题得到了回答。 |
  | 被提及 | 有人 @提及了你。 |

</div>

如果接收者关闭了某个类别，该通知会被跳过。通知可标记为已读，且限定在你所在的公司范围内，
因此你永远不会看到来自其他工作区的活动。

:::note[智能体在做什么]
在想法或任务上进行 @提及或推进阶段的动作，可以唤醒已连接的智能体作出响应，撰写提案、
运行下一轮需求细化，或接手被指派的工作。可观察到的效果是一条回复或一次状态变更；关于该连接
如何建立，参阅[智能体平台参考](/zh/reference/agents/)。
:::
