# 智能体平台

不同平台的安装方式和运行能力并不相同。先根据你的使用场景选择平台，再进入对应章节完成安装。

| 平台 | 支持方式 | 适合谁 | 远程启动 | 持续运行 |
| --- | --- | --- | --- | --- |
| [Claude Code](./claude-code/) | Chorus 第一方 | 使用 Claude Code，希望获得完整 Chorus 工作流和远程会话控制的用户 | 支持 | 支持，通过 Chorus 后台服务 |
| [Codex](./codex/) | Chorus 第一方 | 使用 Codex，希望获得完整 Chorus 工作流和远程会话控制的用户 | 支持 | 支持，通过 Chorus 后台服务 |
| [Kiro](./kiro/) | Chorus 第一方 | 使用 Kiro CLI，希望使用 Chorus 技能和远程会话控制的用户 | 支持 | 支持，通过 Chorus 后台服务 |
| [OpenClaw](./openclaw/) | Chorus 第一方 | 已经运行 OpenClaw，希望在其原生服务中接入 Chorus 的用户 | 支持 | 支持，通过 OpenClaw 原生服务 |
| [DeepSeek Harness](./dsh/) | Chorus 第一方 | 使用 DeepSeek Harness，希望获得 Chorus 工作流的用户 | 不支持 | 不支持 |
| [OpenCode](./opencode/) | 社区维护 | 接受社区集成支持范围的 OpenCode 用户 | 不支持 | 不支持 |
| [Pi](./pi/) | Chorus 第一方，源码安装 | 能够从 Chorus 仓库安装本地包的高级用户 | 不支持 | 不支持 |
| [通用 MCP 客户端](./generic-mcp/) | 协议级接入 | 只需要直接调用 Chorus MCP 工具的用户 | 不支持 | 不支持 |

如果你需要从 Chorus 页面启动智能体并持续管理会话，请选择 Claude Code、Codex、Kiro 或 OpenClaw。只需要在本地交互式使用 Chorus 工具时，可以选择 OpenCode、Pi、DeepSeek Harness 或通用 MCP 客户端。

创建密钥前请阅读[为智能体创建访问权限](/zh/guides/administrator-setup/)。使用 Claude Code、Codex 或 Kiro 远程执行工作时，请在完成平台安装后继续[连接智能体运行环境](/zh/guides/operator-onboarding/)和[管理后台服务](/zh/guides/daemon-operations/)。

## 插件打包了什么

上面每个平台页都会带你完成首次安装与连接验证。本节说明 Chorus 插件在各运行时到底打包了什么，
以及如何保持更新，不重复安装步骤。

插件让 AI 编码运行时成为 Chorus 的协作方：它提供 Chorus MCP 工具、各阶段工作流技能、评审子智能体，
以及会话生命周期自动化。插件按运行时各发布一次，统一命名为 `chorus`。下文完整介绍 Claude Code 与
Codex；OpenClaw、Kiro 和 Pi 是能力更窄或形态不同的移植版本，因此以差异说明加指引的形式呈现，而非
同等对待。

### Claude Code

Claude Code 插件（`chorus@chorus-plugins`）打包了：

- **Chorus MCP 工具**：一个 `.mcp.json` 模板，根据 `CHORUS_URL` 与 `CHORUS_API_KEY` 配置
  Chorus MCP 服务器。`chorus agents add` 会把这两项写入 `~/.claude/settings.json` 的 `env` 块，
  因此交互式会话无需手动导出即可完成认证。
- **工作流技能**：`/chorus` 总览，以及以 `/chorus:idea`、`/chorus:proposal`、
  `/chorus:develop`、`/chorus:review`、`/chorus:quick-dev`、`/chorus:yolo` 调用的各阶段技能。
- **评审子智能体**：三个只读评审者：`chorus:proposal-reviewer`、`chorus:task-reviewer`、
  `chorus:code-reviewer`，各自发布一条 `VERDICT` 评论。
- **会话生命周期 Hook**：自动完成签到、会话发现与创建、心跳、以及任务签出与关闭会话的
  Hook，另有在提交后提醒主智能体派生评审者的 `PostToolUse` Hook。
- **配置开关**：插件的 `userConfig` 选项，用于启用或停用各评审者、限制评审轮次，以及开关
  OpenSpec 模式。

### Codex

Codex 插件（Codex 版 `chorus@chorus-plugins`）打包了：

- **工作流技能**：七个以 `$` 前缀调用的技能：`$chorus`、`$idea`、`$proposal`、`$develop`、
  `$review`、`$quick-dev`、`$yolo`。它们带命名空间，全限定名为 `chorus:<skill>`。
- **评审子智能体**：与 Claude Code 相同的三个只读评审者：`chorus-proposal-reviewer`、
  `chorus-task-reviewer` 与 `chorus-code-reviewer`。
- **会话感知 Hook**：会话启动签到、每轮提醒，以及在提交方案、提交任务或某个想法方案的最后
  一个任务通过验证后触发的 `PostToolUse` 评审提示。Codex 没有与 Claude Code 的 `TeammateIdle`、
  `TaskCompleted` 对应的 Hook。

Codex 的 MCP 服务器**不**随插件打包。Codex 不会在插件 MCP 配置中展开 `${VAR}`，因此
`chorus agents add` 改为把 Codex 配置为不内置密钥：它把
`CHORUS_URL` / `CHORUS_API_KEY` / `CHORUS_AGENT_PROFILE` 写入 `~/.codex/.env`（Codex 在启动时
加载它），并在 `~/.codex/config.toml` 中设置 `bearer_token_env_var = "CHORUS_API_KEY"`，因此
磁盘上不会存储任何字面量密钥。Codex 也没有 `userConfig` 界面，所以评审与 OpenSpec 行为由
技能逻辑控制，而非插件开关。

### 移植版本：OpenClaw、Kiro 与 Pi

这些运行时都有第一方集成，但能力与 Claude Code、Codex 不同。请把下面的说明当作指引，而非同等
能力的保证。

- **OpenClaw**：一个提供 Chorus MCP 工具与工作流技能的插件。它通过 OpenClaw 网关而非
  Chorus 后台服务保持在线，也不提供相同的工作流生命周期 Hook。参见
  [OpenClaw](/zh/reference/agents/openclaw/)。
- **Kiro**：一个提供工具、工作流技能、评审智能体与 Hook 的集成，可按工作区或用户级安装。
  参见 [Kiro](/zh/reference/agents/kiro/)。
- **Pi**：面向高级评估的仅源码集成，提供工具、工作流技能、评审智能体与 Pi Hook。Pi 不是
  Chorus 后台服务后端，无法远程启动、中断或恢复。参见 [Pi](/zh/reference/agents/pi/)。

## 升级插件

原地升级；你的智能体密钥与 Chorus URL 不受影响。

- **任意智能体**：重新运行 `chorus agents add`。它是幂等的，会一次性刷新每个已配置智能体的插件与凭据：

  ```bash
  chorus agents add
  ```

- **Claude Code**：也可以从 `/plugin` 菜单管理插件，或重新执行 marketplace add 与 install 拉取最新版本：

  ```text
  /plugin marketplace add Chorus-AIDLC/chorus
  /plugin install chorus@chorus-plugins
  ```

  重启 Claude Code，然后运行 `/plugin list` 确认新版本已启用。

- **Codex**：重新运行 `chorus agents add` 会刷新插件和 `~/.codex/.env` 凭据，也是轮换智能体密钥的方式。完成后在 Codex 中运行 `/plugins`。

OpenClaw、Kiro 与 Pi 请重新运行 `chorus agents add`，或沿用各自的安装方式升级，步骤见上表中每个运行时的平台页。

## 卸载插件

- **Claude Code**：打开 `/plugin` 菜单，停用或移除 `chorus@chorus-plugins`。移除插件会
  同时移除它的 Hook 与评审子智能体。环境中的智能体密钥不是插件产物，如不再需要请单独删除。
- **Codex**：在 `/plugins` 菜单中停用或移除插件。由于 MCP 服务器是单独配置的，还需从
  `~/.codex/config.toml` 中删除 `[mcp_servers.chorus]` 段，并从 `~/.codex/.env` 中删除 Chorus
  相关密钥，才能彻底断开。系统会保留一次性备份 `config.toml.chorus-bak`。

OpenClaw、Kiro 与 Pi 请通过运行时自带的插件或包管理器移除集成，方式见上表中的平台页。

## 版本对齐

插件与其内置技能统一版本管理，并跟随**单一的 Chorus 应用版本**。插件清单的 `version` 字段与
运行中的 Chorus 版本一致，技能 frontmatter 的 `version` 也随之变动，因此一次插件发布对应它所
面向的应用版本。升级 Chorus 时，请把插件升级到匹配版本；插件报告的版本，也就是其技能版本。

你无需单独管理技能：在 Claude Code 上技能随插件打包、随插件更新一同下发，在 Codex 上技能就在
插件包内。不存在需要单独保持同步的技能安装。

## 面向 Agent

- **触发场景：** 读者（或智能体）来到本页，是为了选择平台，或了解插件在某个运行时提供了什么，
  以及如何升级、卸载、核对版本对齐。首次连接在上表链接的各运行时平台页。
- **约束：**
  - 不要重复首次安装步骤；链接到对应平台页。
  - 准确陈述 Claude Code 与 Codex 的能力：两者都附带全部三个评审者（方案、任务、代码）；只有
    Claude Code 暴露 `userConfig` 开关界面，因此在 Codex 上这些行为由技能与 Hook 直接控制。切勿把
    OpenClaw、Kiro、Pi 说成与主运行时能力对等。
  - 插件与技能是同一个版本号，跟随 Chorus 应用版本；不要描述独立的技能安装。
- **可引用来源：** Claude Code 清单与开关 ，
  `public/chorus-plugin/.claude-plugin/plugin.json`；Codex 清单 ，
  `plugins/chorus/.codex-plugin/plugin.json` 与 `plugins/chorus/README.md`；Hook 与技能分工
  ， `docs/chorus-plugin.md`。上述路径均位于
  [Chorus 仓库](https://github.com/Chorus-AIDLC/Chorus)。
