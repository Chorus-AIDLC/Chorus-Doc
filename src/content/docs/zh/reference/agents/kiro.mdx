Kiro CLI 有 Chorus 官方集成，提供工具、工作流技能、评审智能体和钩子。Kiro 也是受支持的 Chorus 后台服务后端。

开始之前，请安装 Kiro CLI v2，并按照[为智能体创建访问权限](/zh/guides/administrator-setup/)创建智能体密钥。

## 安装集成

用 `chorus` 命令行工具安装 Chorus 集成：

```bash
npm install --global @chorus-aidlc/chorus
chorus agents add --agents kiro
```

在提示时输入 Chorus 地址和智能体密钥。`chorus agents add` 会从你已连接的 Chorus 实例把 Kiro 集成文件下载到 `~/.kiro`（技能、评审智能体和钩子），并把 Chorus MCP 服务器合并进 `~/.kiro/settings/mcp.json`。运行前设置 `KIRO_DIR` 可安装到其他 Kiro 目录。安装完成后请重新启动 Kiro。

## 启用远程启动

如果只在交互式 Kiro 会话中使用 Chorus，可以跳过这一节。否则，请按照
[连接智能体运行环境](/zh/guides/operator-onboarding/)选择 `kiro` 作为运行后端。
先在前台确认连接无误，再按照[管理后台服务](/zh/guides/daemon-operations/)让它保持在线。

## 验证连接

运行 `kiro-cli --agent chorus`，然后让 Kiro 执行 `check in to chorus`，确认响应显示预期的智能体身份和权限。
运行 `/chorus-idea`，确认 Chorus 技能可用。

使用后台服务模式时，在 Chorus 中打开**设置 → 智能体**，确认预期的主机和工作目录处于在线状态。

## 能力与限制

- 该集成提供 Chorus MCP 工具、工作流技能、评审智能体和钩子。
- 后台服务模式支持远程启动、追加指令、中断和恢复。
- 工作区配置优先于用户级的 Kiro 配置。
- 远程工作继承本地用户的访问权限。只注册你信任的工作目录。

通用的操作流程见[从 Chorus 发起远程工作](/zh/guides/remote-control/)和[中断与恢复会话](/zh/guides/session-recovery/)。

## 从终端恢复会话

要在自己的终端里接管正在进行的对话，先在对话界面复制它的会话 ID（对话记录顶部的**复制 session ID**），然后在该对话的工作目录下运行：

```bash
kiro-cli chat --resume-id <sessionId>
```

复制的 ID 与 Chorus 恢复会话时传给 Kiro CLI 的 ID 相同。完整流程见[中断与恢复会话](/zh/guides/session-recovery/#从终端接管会话)。

## 常见问题

- **找不到 Kiro CLI**：安装 Kiro CLI v2，然后重新运行 `chorus agents add`。
- **技能缺失**：检查是否有工作区级安装覆盖了用户级安装，然后重新启动 Kiro。
- **签到返回未授权**：重新运行 `chorus agents add` 以刷新 `mcp.json` 和凭据；后台服务模式下，密钥由后台服务在每次唤醒时提供。
- **后台服务离线**：运行 `chorus daemon status`，然后参阅[排查智能体连接故障](/zh/guides/troubleshooting/)。
