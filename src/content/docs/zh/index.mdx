编程智能体擅长敲键盘，却常常在整个项目层面迷失方向。让它写一个函数，它表现出色；可一旦要它扛下一整个功能，
从厘清需求、做规划、拆分工作，到实现、检查，你又回到了盯着它写提示词、每个会话都要重新解释上下文的状态。
模型越来越聪明，模型周围的活儿却仍然是手工的。

Chorus 就是用来补上这道缺口的一层。它是一套**智能体框架**：包裹在模型之外的结构，把一支由智能体和人组成的团队，
从一个粗糙的想法一路带到交付。模型是大脑，Chorus 是其余的一切。你不必逐个键盘地驱动智能体，而是由它们提出方案，
你来验证。

## 反向对话

大多数工具只有一个方向：你写提示词，AI 来回应，你不断地改提示词直到输出对为止。Chorus 把这个方向反了过来。

你抛进一个粗糙的想法，比如“认证模块需要重构”。智能体不会自己瞎猜，而是带着问题回来：要哪些提供方，OAuth 还是
SAML？需求厘清之后，它交给你一份方案：一份简短的规格，加上要做的几项任务，并把任务之间的依赖也理好，然后等你点头。
只有在你同意之后它才动手写代码；写完时给你看的是通过的测试，而不是让你凭空信任的一大堆改动。

你的角色从“写提示词”转向“审阅方案”。你在改动还很便宜的阶段就批准计划，把走偏的方向拦在方案环节，而不是等代码
写完才发现。这就是整件事的核心：**AI 提出，人类验证。**

## 工作如何流转

每个想法都走同一条路径，不经过明确的交接就不会进入下一阶段：

**想法 → 提案 → 文档 + 任务 → 执行 → 验证 → 完成**

你写下一个想法。智能体问上几个澄清问题，再把答案变成一份提案：一份简短的规格，加上实现它所需的任务，任务之间的
依赖也已理清。你审阅并批准。随后智能体认领这些任务，在计划允许的地方并行推进，并随时汇报。任何东西被标记为完成
之前，都会对照提案的要求做检查。你在每一次交接处都在场，却不必亲自驱动每一步。

[AI-DLC 工作流指南](/zh/guides/ai-dlc-workflow/)会端到端地走完这条路径。

## 谁在干活

你是那个审阅的人。真正的执行分散在不同职责与权限的智能体身上，每个智能体只能碰它的角色允许的部分：

- **PM 智能体**把想法变成提案：厘清需求、撰写规格，并把工作拆成任务。
- **开发智能体**认领这些任务，编写代码、汇报进度，并把结果提交审阅。多个开发智能体可以同时处理互不依赖的任务。
- **管理员智能体**治理项目：创建项目、批准提案、验证完成的工作。

这些智能体可以跑在 Claude Code、Codex、OpenClaw，或任何兼容 MCP 的智能体上，支持范围见
[智能体平台](/zh/reference/agents/)参考。

## 你能得到什么

Chorus 是让这种协作真正粘合起来的连接组织：

- **你看得见正在发生什么**。每个智能体的活动都实时可见：哪个智能体、哪个子智能体，正在处理哪个任务。
- **你自带智能体**。不锁定任何厂商或模型，任何兼容 MCP 的智能体都能加入。
- **整套东西都归你**。Chorus 以 AGPL-3.0 开源，运行在你自己的基础设施上。
