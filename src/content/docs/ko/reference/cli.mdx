# `chorus` CLI

`chorus` 명령(`@chorus-aidlc/chorus`로 게시됨)은 세 가지 일을 합니다. Chorus 서버를 실행하고, 이
컴퓨터의 코딩 에이전트를 구성하며, 셸에서 Chorus MCP 엔드포인트를 호출합니다. 전역으로 설치합니다.

```sh
npm install --global @chorus-aidlc/chorus
chorus --version
```

전체 플래그 목록은 `chorus --help` 또는 `chorus <command> --help`를 실행하세요.

## 명령 한눈에 보기

| 명령 | 하는 일 |
| --- | --- |
| `chorus` | Chorus 서버를 시작합니다(서브커맨드가 없을 때의 기본값). [Docker로 배포](/ko/guides/deploy-docker/)를 참고하세요. |
| `chorus upgrade` / `chorus update` | npm 전역 CLI를 업데이트합니다. `--plugins`로 설정된 Chorus 플러그인도 갱신합니다. |
| `chorus agents` | 이 컴퓨터의 에이전트를 구성합니다 — `list`(기본), `add`, `remove`, 그리고 `run`(하나 실행). |
| `chorus mcp` | 네이티브 MCP 클라이언트 — 도구를 `call`하거나, 자신의 UUID를 출력하거나(`whoami`), 호출 가능한 도구를 `list`합니다. |
| `chorus login` | 에이전트로 인증하고 연결을 `~/.chorus/daemon.json`에 저장합니다. |
| `chorus daemon` | Chorus가 깨울 수 있도록 런타임을 온라인으로 유지합니다. [Chorus 데몬 운영](/ko/guides/daemon-operations/)을 참고하세요. |

:::note[0.17.0에서 이름이 바뀜]
`chorus init`은 이제 `chorus agents add`입니다(플래그 동일). 에이전트별 `install-*.sh` 스크립트는
폐기되었으며, 이제 그저 `chorus agents add`로 안내할 뿐입니다.
:::

## CLI와 플러그인 업그레이드

Chorus 0.20.0부터 다음 명령을 사용할 수 있습니다.

```sh
chorus upgrade             # CLI만 업데이트
chorus upgrade --plugins   # CLI, 이어서 설정된 Chorus 플러그인
chorus update --plugins    # upgrade의 별칭
```

검증 가능한 `@chorus-aidlc/chorus` **npm 전역 설치** 를 지원합니다. npm의 최신 안정 버전을 확인하고 현재 설치와 같은 npm prefix에 업데이트한 뒤 설치된 버전을 검증합니다. 이미 같거나 더 높은 버전이면 재설치하거나 다운그레이드하지 않지만 `--plugins`는 실행합니다. 소스 체크아웃, 링크 설치, 다른 패키지 관리자의 설치는 지원하지 않습니다. 이 명령이 없는 이전 CLI에서는 먼저 `npm install --global @chorus-aidlc/chorus@latest`로 새 버전을 설치하세요.

### `--plugins`의 업데이트 범위

`~/.chorus/daemon.json`을 읽어 Claude Code, Codex, Kiro, Pi로 명시된 항목을 처리합니다. 데몬 깨우기가 꺼진 항목도 포함됩니다. 각 항목의 `env`, `PATH`, 사용자 지정 설정 홈으로 대상을 정합니다. 공유 경로는 한 번만, 서로 다른 홈은 별도로 처리합니다. 현재는 기본 파일만 읽으며 `CHORUS_DAEMON_CONFIG_PATH`는 사용하지 않습니다.

- **Claude Code와 Codex**: 호스트의 플러그인 기능으로 Chorus 플러그인을 갱신합니다.
- **Kiro**: 항목에 설정된 Chorus 인스턴스에서 템플릿을 가져옵니다. 새 템플릿을 받으려면 해당 서버를 먼저 업그레이드하세요. 같은 대상 경로에 충돌하는 인스턴스 URL이 있으면 미완료로 보고합니다.
- **Pi**: `@chorus-aidlc/chorus-pi`와 `pi-mcp-adapter`만 업데이트합니다. 버전 고정, 범위, latest가 아닌 태그는 유지되며 항상 미완료로 보고됩니다. 최신 버전으로 업데이트하려면 해당 제한을 제거하세요. Pi가 개별 패키지 업데이트를 지원하지 않으면 제한을 알리고 모든 확장을 업데이트하지 않습니다.

호스트 CLI가 있으면 누락된 Chorus 플러그인을 설치할 수 있습니다. 등록 정보와 자격 증명은 유지하며 호스트 CLI 자체를 설치하거나 업데이트하지 않습니다. 설정 파일을 변경하기 전에 `<file>.chorus-upgrade.bak`으로 사본을 저장하며, 다음 업그레이드 때 교체됩니다. `offline` 또는 알 수 없는 유형(기본 OpenCode, OpenClaw, dsh 항목 포함), 각 항목의 `PATH`에 호스트가 없는 경우는 건너뛰고 **INCOMPLETE** 로 표시합니다. 이 호스트에는 [플랫폼별 설정 또는 업데이트 절차](/ko/reference/agents/)를 사용하세요.

### 완료 상태와 적용

명령은 대화형 확인 없이 실행됩니다. 종료 코드 **0** 은 요청한 작업 전체 완료, **1** 은 실패 또는 미완료 대상이 있음을 뜻합니다. 데몬 파일이 없거나 에이전트 목록이 비어 있으면 변경 없이 성공합니다. 파일을 읽을 수 없거나 형식이 잘못되면 실패합니다. CLI 업데이트 실패 시 플러그인 작업은 실행하지 않습니다. 개별 플러그인 실패 후에도 나머지 대상을 처리하고 완료된 업데이트는 유지하며, 자동 롤백은 하지 않습니다.

npm 설치는 진행 상황을 출력하며 설치 시간 제한이 없습니다. 실패하면 표시된 npm 오류를 확인하세요. `EACCES` 또는 `EPERM`이면 사용자 소유의 Node 설치를 쓰거나 관리자에게 시스템 npm prefix 업데이트를 요청하세요. Chorus는 자동으로 권한을 올리지 않습니다. 업데이트 후 새 에이전트 세션을 시작하고 적절한 시점에 `chorus daemon restart`를 실행하세요. 데몬과 실행 중인 세션은 자동으로 재시작되지 않습니다.

## 에이전트 구성하기 — `chorus agents`

`chorus agents add`는 컴퓨터의 코딩 에이전트를 Chorus에 연결하는 단 하나의 명령입니다. 이미 설치되어
있는 에이전트를 감지하고, 각 에이전트 자신의 플러그인 메커니즘을 통해 그 Chorus 플러그인을 설치하며,
Chorus URL과 에이전트 키를 한 번 받아 `~/.chorus/daemon.json`에 저장합니다. Claude Code, Codex,
DeepSeek Harness의 경우에는 인증 정보를 그 에이전트 자신의 구성에도 쓰므로, 대화식 세션이 수동 환경
설정 없이 인증합니다([인증 정보는 어디로 가는가](#인증-정보는-어디로-가는가) 참조).

```sh
chorus agents add                     # interactive: detect, pick, configure
chorus agents add --all --yes         # configure every detected agent, no prompts
chorus agents add --agents claude,codex \
  --url https://chorus.example.com --api-key cho_xxx
```

멱등적이므로 — 에이전트를 추가하거나, 플러그인을 새로 고치거나, 키를 교체하려고 다시 실행해도
안전합니다. 감지되었지만 아직 설치되지 않은 에이전트도 선택할 수 있습니다. 지원되는 에이전트는 Claude
Code, Codex, Kiro, Pi, opencode, OpenClaw, DeepSeek Harness입니다. `pi`가 PATH에 있으면
`pi-mcp-adapter`와 `chorus-pi`를 자동 설치하고, 없으면 수동 설치 방법을 안내합니다.

유용한 플래그(`chorus agents add --help`가 전부 나열합니다):

- `--agents <a,b>` / `--all` — 구성할 에이전트.
- `--url` / `--api-key` — 인증 정보를 비대화식으로 제공(환경 변수: `CHORUS_URL` / `CHORUS_API_KEY`).
- `--update-installed` — 기존 설치를 갱신합니다. Pi는 `pi update --extensions`를 실행합니다.
  `pi install`만 반복해서는 이미 설치된 패키지가 업데이트되지 않습니다.
- `--dsh-profile <name>` — 번들을 설치할 DeepSeek Harness 프로필.
- `--daemon-wake <a,b>` / `--daemon-wake-all` — 지정한(또는 깨울 수 있는 모든) 에이전트를 데몬 웨이크 대상으로 선택합니다. 깨울 수 있는 에이전트(Claude Code, Codex, Kiro, Pi)는 기본적으로 "파킹" 상태로 추가됩니다. `chorus mcp`로는 접근할 수 있지만, 여기서 명시적으로 선택하거나 TTY에서 에이전트별 프롬프트에 답하기 전까지는 데몬이 깨우지 않습니다.
- `--daemon-autostart` — 데몬 부팅 서비스도 함께 설치·활성화(Linux systemd / macOS launchd).
- `-y, --yes` — 확인 건너뛰기(TTY가 아니면 암묵적으로 적용되며, 이때는 `--agents` 또는 `--all`을 전달해야 합니다).

구성된 에이전트를 나열하고 제거합니다.

```sh
chorus agents                     # list configured agents (name, UUID, backend)
chorus agents remove <name|uuid>  # remove one (match by name or UUID)
```

`chorus agents`는 API 키를 절대 출력하지 않습니다. 나열된 이름이나 UUID는 `chorus mcp --agent` 또는
`CHORUS_AGENT_PROFILE` 환경 변수에 쓸 수 있는 유효한 값입니다.

## 에이전트 실행하기 — `chorus agents run`

`chorus agents run`은 구성된 에이전트를 Chorus 연결이 이미 연결된 상태로 터미널에서 실행합니다 —
데몬 웨이크의 포그라운드 짝입니다. 자식 프로세스는 부모 셸의 환경을 바꿀 수 없으므로, 이 명령은
연결을 실행되는 에이전트 프로세스에 직접 주입합니다. 따라서 무엇도 수동으로 내보낼 필요가 없습니다.

```sh
chorus agents run --name work -- --model opus        # 에이전트 "work"를 실행하고 --model opus를 전달
chorus agents run                                    # 구성된 에이전트가 하나뿐이면 그것을 실행
chorus agents run --name work --type codex -- resume # 백엔드를 재정의하고 `resume`을 그대로 전달
```

- **어느 에이전트인가** — `--name <name|uuid>`가 `~/.chorus/daemon.json`의 `agents[]`에서 고릅니다. 에이전트가
  하나뿐이면 생략할 수 있고, 여러 개면 `--name`을 전달(또는 `CHORUS_AGENT_PROFILE` 설정)해야 하며,
  그러지 않으면 명령은 추측하지 않고 오류를 냅니다.
- **무엇이 주입되는가**(실행되는 프로세스에만 주입되며, 셸에는 들어가지 않고 출력되지도 않습니다):
  `CHORUS_URL`, `CHORUS_API_KEY`, `CHORUS_AGENT_PROFILE`.
- **어느 바이너리인가** — 기본값은 에이전트에 저장된 백엔드이고 `--type`으로 재정의합니다. 종류는 각각
  `claude`, `codex`, `kiro-cli`, `pi`, `opencode`, `openclaw`, `dsh`에 매핑됩니다.
  opencode / OpenClaw / DeepSeek Harness로 추가한 에이전트는 `offline`로 저장되므로(데몬이 자동으로
  깨우지 않음), 실행하려면 `--type`을 명시하세요.
- **패스스루** — `--` 뒤의 모든 것은 에이전트에 그대로 전달되어 전체 플래그 표면을 쓸 수 있습니다.
  에이전트는 당신의 터미널을 이어받고, `chorus agents run`은 그 종료 코드로 종료합니다.

### 영구 args/env와 일회성 재정의

선택된 `agents[]` 항목에 `args`(문자열 배열, 기본값 `[]`)와 `env`(문자열을 문자열에 매핑하는 객체, 기본값 `{}`)를 둘 수 있습니다. 데몬 웨이크와 포그라운드 실행 모두 사용합니다. 비어 있지 않은 `agents[]`가 있으면 최상위 설정을 상속하지 않으며, 잘못된 위치의 필드는 오류가 됩니다. [데몬 가이드](/ko/guides/daemon-operations/)에서 복사 가능한 모델/사고/env 예제, 평면 파일 이전, 검증, 비밀 보호 주의 사항을 확인하세요. 값은 리터럴이며 셸 확장, dotenv 로딩, 비밀 조회를 하지 않습니다. Env는 자식에만 영향을 주며 `CHORUS_*`와 중첩 Claude 컨텍스트 이름 `CLAUDECODE` / `CLAUDE_CODE_ENTRYPOINT`는 대소문자와 무관하게 예약되어 있습니다. 설정하면 조용히 삭제되는 대신 오류가 발생합니다. 영구 인수는 알려진 세션, 프롬프트, 프로토콜, 작업 디렉터리, MCP, 권한 제어를 재정의하거나 `--` / `-` 표시자 및 도움말/검사 종료 옵션을 포함할 수 없습니다. 네이티브 재개 명령을 포함한 명시적 포그라운드 인수는 그대로 유지됩니다. 알려진 충돌을 막는 것이며 샌드박스는 아닙니다.

새 `chorus agents run`은 매번 파일을 다시 읽습니다. 데몬 변경은 `chorus daemon restart`가 필요하며, 두 경로 모두 이미 실행 중인 자식은 갱신하지 않습니다. `--type`은 검증과 재정의 판정에 쓰는 백엔드를 선택할 뿐 백엔드 플래그를 변환하지 않습니다.

아래 옵션에 한해, 선택된 명령 범위에서 명시적으로 지정하면 구성의 대응 옵션과 그 값을 제거합니다.

| 실제 백엔드 | 인식하는 재정의 |
| --- | --- |
| `claude-code` / `claude` | `--model`, `--effort` |
| `codex` | `--model` / `-m` / 구성 키 `model`; 구성 키 `model_reasoning_effort` |
| `kiro` | `--model`, `--effort` |
| `pi` | `--model`, `--thinking`, `--provider` |
| `opencode` | `--model` / `-m` |
| `openclaw` | `agent`의 `--model`, `--thinking`(`-m`은 모델이 아닌 메시지) |
| `dsh` | 없음. 대신 `DSH_PROVIDER` / `DSH_MODEL` 환경 변수 사용 |

판정은 `--option value`, `--option=value`, 그리고 표에 `-m`이 있는 경우 `-mVALUE` / `-m=VALUE`를 인식합니다. Codex는 `-c key=value`, `-ckey=value`, `-c=key=value`, `--config key=value`, `--config=key=value`를 지원합니다. 표의 두 키만 우선순위 처리에 참여하며 무관한 구성 항목은 유지됩니다. 백엔드도 해당 표기를 지원해야 합니다. Pi 0.85.1의 `--model`, `--thinking`, `--provider`는 등호 형식 대신 값을 분리해서 전달하세요.

```sh
chorus agents run --name pi-worker -- --model anthropic/claude-sonnet-4-6 --thinking medium
chorus agents run --name codex-worker -- exec --model gpt-5.4 -c model_reasoning_effort=high
```

**하위 명령**: 영구 인수는 인식한 가장 깊은 명령 뒤에 삽입됩니다. 대상은 Codex의 `exec`, `exec resume`, `resume`, Kiro의 `chat`, OpenClaw의 `agent`입니다. 명시적 재정의도 같은 범위에 두세요. `--model chosen exec`가 아니라 `exec --model chosen`을 사용합니다. 루트/부모 명령의 모델 옵션은 자식 명령에 구성된 모델을 제거하지 않습니다. Codex `-c`/`--config` 키는 범위를 넘어 적용됩니다. 인식한 명령이 없으면 구성 인수를 맨 앞에 둡니다. 다른 명령 경로는 추론하지 않으므로 호환되지 않는 영구 인수를 빼고 네이티브 패스스루를 사용하세요.

**알 수 없는 옵션**: 영구 `args`는 일반적인 미지의 플래그를 허용하지만 다음 토큰이 값인지 프롬프트인지 추측하지 못합니다. 백엔드가 지원하면 `["--future=value"]`를 사용하고 `["--future", "value"]`는 쓰지 마세요. 알려진 옵션에는 요구되는 값을 제공해야 합니다. 미지의 옵션이나 반복 가능한 옵션은 선택 범위에서 구성 후 명시 순서를 유지하며, 일반적인 후순위 우선 규칙은 보장하지 않습니다. 모호한 명시적 옵션(알 수 없고 인라인 값도 없음) 뒤에서는 재정의 추론을 멈춥니다. 알려진 재정의를 앞에 두거나 지원되는 인라인 값을 사용하세요. 바깥쪽 Chorus 구분자를 제거한 뒤 에이전트 인수 안의 첫 단독 `--`에서도 분석이 멈춥니다. 명령 탐색은 위치 프롬프트, 알 수 없는 명령, 모호한 옵션에서 멈추며 알려진 옵션 값을 건너뜁니다. 명시적 토큰은 모두 그대로 전달되므로 백엔드 플래그와 버전 호환성은 직접 확인하세요. Windows `.cmd`/`.bat` 제한은 데몬 가이드를 참고하세요.

Codex 데몬은 영구 인수를 모델 옵션과 허용된 `-c` / `--config` 설정으로 더 제한합니다. 다른 옵션은 포그라운드에서 사용할 수 있어도 데몬 실행 전에 오류가 발생합니다. [Codex 데몬 설정](/ko/reference/agents/codex/#모델-옵션과-세션-연속성)을 참고하세요.

## 셸에서 MCP 도구 호출하기 — `chorus mcp`

`chorus mcp`는 네이티브 MCP 클라이언트로, 스크립트나 터미널에서 어떤 Chorus 도구든 호출하는, 토큰이
필요 없는 경로입니다. 이전의 `chorus-api.sh` / `chorus-mcp-call.sh` 래퍼를 대체합니다.

```sh
chorus mcp call <tool> '<json>'                  # call a tool with a JSON argument object
chorus mcp call <tool> --arg key=value           # set one string argument
chorus mcp call <tool> --arg-file content=<path> # stream a file's raw bytes into an argument
chorus mcp whoami                                 # print this agent's own UUID
chorus mcp list                                   # list the tools this agent may call
```

`--arg-file`는 큰 내용 — 문서 본문이나 OpenSpec 파일 — 이 모델을 거쳐 다시 입력되지 않고 도구에
도달하는 방법입니다. 성공하면 `chorus mcp call`은 도구 결과를 stdout에 그대로 출력하고, 도구나 전송
오류는 0이 아닌 종료 코드와 함께 stderr로 나갑니다.

아이덴티티는 다음 순서로 해석됩니다: `--agent <name|uuid>` → 명시적 `--url` + `--api-key` 플래그 →
`CHORUS_AGENT_PROFILE` → `CHORUS_URL` + `CHORUS_API_KEY` → 에이전트가 하나뿐일 때 그 단일 구성 에이전트.

## 연결 환경 변수

| 변수 | 의미 |
| --- | --- |
| `CHORUS_URL` | Chorus 인스턴스 URL. |
| `CHORUS_API_KEY` | 에이전트 API 키(`cho_…`). |
| `CHORUS_AGENT_PROFILE` | 대신 행동할 구성된 에이전트의 이름 또는 UUID(선택). 설정되면 `chorus mcp`가 그 에이전트의 키를 `~/.chorus/daemon.json`에서 읽으므로, `CHORUS_API_KEY`를 내보낼 필요가 없습니다. |

데몬이 깨운 세션은 `CHORUS_AGENT_PROFILE`를 자동으로 받습니다. 특정 구성 에이전트로 행동해야 하는
대화식 셸에서만 직접 설정하면 됩니다.

## 인증 정보는 어디로 가는가

`chorus agents add`는 검증된 인증 정보를 항상 `~/.chorus/daemon.json`에 씁니다(모드 `0600`. 키는 절대
출력되지 않습니다). 세 에이전트에 대해서는 대화식 세션이 수동 내보내기 없이 인증하도록 그 에이전트
자신의 구성에도 인증 정보를 심습니다.

| 에이전트 | 추가 인증 정보 저장소 |
| --- | --- |
| Claude Code | `~/.claude/settings.json`의 `env` 블록(`CLAUDE_CONFIG_DIR`를 따름). |
| Codex | `~/.codex/.env`(`CODEX_HOME`을 따름). Codex는 keyless `config.toml` 항목을 통해 환경 변수에서 키를 읽습니다. |
| DeepSeek Harness | `$DSH_HOME/.env`. |

Kiro, opencode, OpenClaw는 자신의 설치된 구성에서, 또는 데몬이 깨운 Kiro의 경우에는 데몬이 깨울 때마다
내보내는 환경 변수에서 인증 정보를 읽습니다.

## 에이전트용

- **트리거.** 이 페이지에 오는 이유는 CLI를 설치·업그레이드하거나, 에이전트를 구성하거나
  (`chorus agents add`), 셸에서 Chorus 도구를 호출하기(`chorus mcp call`) 위해서입니다.
- **제약.** 문서 미러와 그 밖의 큰 내용 호출에는 `chorus mcp call <tool> '<json>' --arg-file content=<file>`을
  우선하고, `chorus`가 `PATH`에 없을 때만 `chorus-api.sh` / `chorus-mcp-call.sh`로 대체하세요. API
  키를 명령줄이나 셸 기록에 절대 붙여 넣지 말고, `chorus agents add` / `chorus login`이 받아 가게
  하세요.
- **출처.** 권위 있는 플래그 표면은 `chorus --help`와 `chorus <command> --help`를 실행하세요. 항상
  설치된 버전과 일치합니다.
