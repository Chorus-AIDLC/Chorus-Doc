# Codex

Codex에는 도구, 워크플로 스킬, 훅을 갖춘 제1자 Chorus 통합이 있습니다. 지원되는 Chorus 데몬
백엔드이기도 합니다.

설치 전에 [에이전트 액세스 준비](/ko/guides/administrator-setup/)에 따라 에이전트 키를
만드세요.

## 통합 설치

아직 Codex가 없다면 설치합니다.

```bash
npm install --global @openai/codex
```

그런 다음 `chorus` CLI로 Chorus 통합을 설치합니다.

```bash
npm install --global @chorus-aidlc/chorus
chorus agents add --agents codex
```

프롬프트가 나오면 Chorus URL과 에이전트 키를 입력합니다. `chorus agents add`는 Codex 플러그인을 설치하고 Codex를 keyless로 구성합니다. `CHORUS_URL`, `CHORUS_API_KEY`, `CHORUS_AGENT_PROFILE`를 `~/.codex/.env`에 쓰고 `~/.codex/config.toml`에 `bearer_token_env_var = "CHORUS_API_KEY"`를 설정하므로, Codex는 리터럴 키가 아니라 환경 변수에서 자신의 키를 읽습니다. 그 뒤 Codex를 재시작하세요.

## 원격 시작 활성화

대화식 Codex 세션에서만 Chorus를 사용한다면 이 섹션을 건너뛰세요. 그렇지 않다면
[런타임 연결](/ko/guides/operator-onboarding/)에 따라 백엔드로 `codex`를 선택합니다.
[데몬 운영](/ko/guides/daemon-operations/)으로 온라인 상태를 유지하기 전에, 포그라운드에서
연결을 확인하세요.

## 0.20.0의 데몬 동작

데몬은 깨울 때마다 독립된 `codex app-server --listen stdio://` 프로세스로 한 턴을 실행합니다. 검증된 최소 기준은 **codex-cli 0.157.1** 입니다. 이전 버전은 검증되지 않았으며 필요한 프로토콜을 지원하지 않으면 실행에 실패합니다. `codex exec`로 돌아가는 대체 경로나 전환 옵션은 없습니다. 사용자 지정 `CODEX_HOME`에도 Chorus 통합을 설치하세요. Chorus 플러그인 업데이트가 Codex CLI 자체를 업그레이드하지는 않습니다.

### 모델 옵션과 세션 연속성

데몬 `args`는 모델 선택(`--model` / `-m`)과 `model_reasoning_effort` 같은 허용된 `-c` / `--config` 설정을 지원합니다. `--oss`, 이미지 입력, 알 수 없는 옵션 등은 실행 전에 오류가 발생합니다. 전송, 작업 디렉터리, 권한, 관리형 MCP 제어는 보호됩니다. 지원되는 설정이나 [CLI](/ko/reference/cli/)의 명시적인 포그라운드 명령을 사용하세요. `chorus agents run --type codex -- exec ...` 및 `... -- resume ...`의 기존 동작은 유지됩니다.

이전 `exec` 백엔드가 만든 스레드도 현재 작업 디렉터리와 권한 정책으로 재개합니다. 명확한 “no rollout found” 응답일 때만 대체 스레드를 한 번 만들고 대화에 연속성 알림을 표시합니다. 다른 재개 오류는 실행을 중단하고 저장된 매핑을 유지합니다. 세션 매핑 읽기 실패 시 경고와 함께 새로 시작하며, 쓰기 실패 시 이후 재개에 영향이 있을 수 있음을 알립니다. 새 메시지는 후속 턴에 대기하며 실행 중인 턴에 끼어들지 않습니다. 토큰 사용량은 누적 카운터의 차이로 계산합니다. 재개한 스레드에 신뢰할 수 있는 기준값이 없으면 해당 턴 사용량을 생략하여 과거 사용량을 중복 계산하지 않습니다.

### 제한 모드와 도구 승인

`--chorus-only`는 읽기 전용을 유지하고 대화형 승인과 해당 턴의 네트워크 접근을 비활성화합니다. 네이티브 승인이나 사용자 입력 요청은 거부하며, 안전하게 거부할 수 없는 요청은 실행을 실패시킵니다. 질문은 Chorus 댓글이나 요구사항 구체화로 전달하세요. 검증된 Codex에서는 승인이 필요한 Chorus MCP 도구도 거부될 수 있으며 `chorus_checkin`도 포함됩니다. 턴 완료가 MCP 호출 성공을 뜻하지는 않습니다.

체크인을 허용하기로 했다면 `~/.codex/config.toml`(또는 에이전트의 `CODEX_HOME/config.toml`)에 다음을 명시하세요.

```toml
[mcp_servers.chorus.tools.chorus_checkin]
approval_mode = "approve"
```

0.157.1의 신규 및 재개 스레드에서 읽기 전용과 대화형 승인 비활성화를 유지한 채 이 설정을 검증했습니다. 체크인만 허용하며 댓글과 작업 업데이트는 각각 명시적인 허용과 검증이 필요합니다. 데몬 `args` 대신 Codex 설정에 넣으세요. 데몬은 대신 승인하지 않습니다.

### 중단과 문제 해결

허가된 중단은 `turn/interrupt`를 보내며 시작 중 취소는 전송을 닫습니다. 이어서 제한 시간 내에 프로세스 트리를 정리합니다. Windows에는 Windows PowerShell(`Get-CimInstance`)과 `taskkill`이 필요합니다. Windows는 플랫폼 테스트로, Linux는 실제 실행으로 검증되었습니다.

시작 또는 프로토콜 오류에서는 `codex --version`, 로그인, 모델 설정, 로컬 세션 저장소 권한을 확인하세요. 초기화 제한은 30초, 시작 단계 RPC 응답은 60초, 정리는 10초입니다. 실행 중인 턴에는 비활성 시간이나 전체 실행 시간 제한이 없으므로 멈췄다면 **중단** 을 사용하세요. `CLOSED`는 정보성 진단입니다. 프로세스가 0으로 종료되어도 실패, 중단, 종료 이벤트 누락을 성공으로 처리하지 않습니다. [세션 복구](/ko/guides/session-recovery/)도 참고하세요.

## 연결 확인

Codex를 열고 `check in to chorus`를 요청합니다. 응답이 예상한 에이전트 신원과 권한을 보여
주는지 확인합니다. `/plugins`와 `/hooks`를 사용해 Chorus 플러그인과 훅이 활성화되어 있는지도
확인할 수 있습니다.

데몬 모드에서는 Chorus의 **설정 → 에이전트**를 열고 예상한 호스트와 작업 디렉터리가 온라인인지
확인합니다.

## 기능과 제한

- 통합은 Chorus MCP 도구, 워크플로 스킬, 그리고 Codex 훅을 제공합니다.
- 데몬 모드는 원격 시작, 후속 지시, 중단, 재개를 지원합니다.
- Codex에는 사전 생성 훅이 없으므로, Chorus 워크플로 스킬이 서브 에이전트 세션을 명시적으로
  관리합니다.
- 원격 작업은 로컬 사용자의 접근 권한을 상속합니다. 신뢰하는 작업 디렉터리만 등록하세요.

공통 운영 절차는 [원격 제어](/ko/guides/remote-control/)와
[세션 복구](/ko/guides/session-recovery/)를 사용하세요.

## 터미널에서 재개하기

자신의 터미널에서 진행 중인 대화를 넘겨받으려면, 채팅 UI에서 해당 세션 ID를 복사한 뒤
(대화 기록 헤더의 **Copy session ID**), 그 대화의 작업 디렉터리에서 실행합니다.

```bash
codex exec resume <thread_id>
```

Codex는 자체 thread id를 생성하므로, 복사한 값은 그 thread id이며 Chorus가 제공한 세션 ID가
아닙니다. 그것은 Chorus가 실행을 재개할 때 Codex에 되돌려 주는 바로 그것입니다. 전체 흐름은
[세션 중단과 재개](/ko/guides/session-recovery/#터미널에서-이어받기)를 참고하세요.

## 자주 발생하는 문제

- **`codex`를 찾을 수 없음:** `@openai/codex`를 전역으로 설치하고 `chorus agents add`를 다시
  실행합니다.
- **체크인이 승인되지 않음:** 에이전트 키를 교체하고 `chorus agents add`를 다시 실행합니다
  (`~/.codex/.env`를 새로 고칩니다).
- **플러그인 또는 훅이 비활성화됨:** `/plugins`와 `/hooks`에서 활성화한 뒤 Codex를 재시작합니다.
- **데몬이 오프라인:** `chorus daemon status`를 실행한 뒤
  [문제 해결](/ko/guides/troubleshooting/)을 참고합니다.
