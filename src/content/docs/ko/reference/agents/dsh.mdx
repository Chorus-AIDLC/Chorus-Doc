DeepSeek Harness (dsh)는 공식 npm 번들 `@chorus-aidlc/chorus-dsh`를 통해 Chorus에 연결됩니다. 이 번들은 Chorus MCP 도구, 워크플로 스킬, 페르소나를 dsh 프로필에 추가합니다. dsh는 대화형으로 사용할 수 있으며, dsh `0.1.2-rc.1`부터는 Chorus가 데몬 백엔드로서 dsh를 무인으로 깨울 수도 있습니다.

시작하기 전에 dsh `0.1.2-rc.1` 이상과 `pnpm`을 설치하고, [에이전트 액세스 준비](/ko/guides/administrator-setup/)에 따라 에이전트 키를 만드세요.

## 번들 설치와 인증 정보 저장

`chorus agents add`는 번들을 dsh 프로필에 설치하고 인증 정보를 `$DSH_HOME/.env`에 한 번에 씁니다. 프로필 이름은 `--dsh-profile`로 지정합니다.

```bash
npm install --global @chorus-aidlc/chorus
chorus agents add --agents dsh --dsh-profile <name>
```

프롬프트가 나오면 Chorus URL과 에이전트 키를 입력합니다. dsh는 도구 하위 프로세스에서 인증 정보 형태의 변수를 제거하므로, `chorus agents add`는 `CHORUS_URL`, `CHORUS_API_KEY`, `CHORUS_AGENT_PROFILE`를 `$DSH_HOME/.env`에 저장하고, dsh가 이를 세션에 로드합니다. dsh는 다음 순서로 인증 정보를 해석합니다: 환경 변수 → `$DSH_HOME/.credentials.yaml` → `<cwd>/.env` → `$DSH_HOME/.env`.

번들을 직접 추가하려면 다음을 실행한 뒤(dsh 프로필은 pnpm 워크스페이스 루트이므로 `-w`가 필요합니다), `$DSH_HOME/.env`에 인증 정보를 직접 설정하세요.

```bash
dsh plugin --profile <name> add @chorus-aidlc/chorus-dsh -w
```

## 연결 확인

프로필을 실행합니다.

```bash
dsh --profile <name>
```

"check in to chorus"라고 요청하세요. Chorus에서 **설정 → 에이전트**를 열고 dsh 연결이 온라인인지 확인합니다.

## 데몬 백엔드로 실행하기 (선택)

dsh `0.1.2-rc.1`부터 Chorus는 Claude Code, Codex, Kiro를 깨우는 것과 동일하게 dsh를 무인으로 깨울 수 있습니다. 먼저 `chorus agents add --agents dsh`로 인증 정보를 한 번 저장한 뒤, dsh 백엔드를 선택해 데몬을 시작합니다.

```bash
chorus daemon --agent dsh
```

데몬은 dsh를 처음 깨울 때 자체 관리형 `sdk` 프로필을 빌드하고 검증하므로, 이 경로에는 인증 정보만 있으면 되고 프로필을 수동으로 설치할 필요가 없습니다. `dsh` 본체는 `PATH`에 있어야 합니다(또는 `CHORUS_DSH_PATH` 설정). Chorus는 dsh 런타임을 포함하지 않습니다. dsh에 아이디어나 작업을 배정하거나 dsh를 @멘션하면 dsh가 깨어납니다.

깨울 때마다 **새로운** dsh 세션이 시작됩니다(dsh에는 깨우기 사이의 네이티브 세션 재개가 없습니다). Chorus는 대화 컨텍스트를 할당된 아이디어/작업에 보관하고, 깨어난 dsh 에이전트는 Chorus MCP 도구로 이를 다시 읽어옵니다.

## 기능과 제한

- 번들은 Chorus MCP 도구, 워크플로 스킬, Chorus 페르소나를 제공합니다.
- dsh는 자체 프로필을 통해 대화형으로 동작하며, 무인 데몬 백엔드(`chorus daemon --agent dsh`)로도 동작합니다.
- 깨울 때마다 dsh는 새 세션을 시작합니다. 깨우기 사이의 네이티브 세션 재개는 없으며, 연속성은 깨우기와 연결된 Chorus 리소스에 저장된 맥락으로 유지됩니다.

## 자주 발생하는 문제

- **`dsh` 또는 `pnpm`을 찾을 수 없음:** 두 전제 도구를 설치하고 새 셸을 엽니다.
- **`ERR_PNPM_ADDING_TO_ROOT`:** `-w`를 붙여 명령을 다시 실행하세요. dsh 프로필은 pnpm 워크스페이스 루트입니다.
- **패키지를 찾을 수 없음:** 레지스트리 액세스와 패키지 이름 `@chorus-aidlc/chorus-dsh`를 확인한 뒤 추가 명령을 다시 실행합니다.
- **체크인이 승인되지 않음:** `CHORUS_URL`과 `cho_` 에이전트 키가 `$DSH_HOME/.env`에 저장되었는지 확인한 뒤(`chorus agents add --agents dsh --dsh-profile <name>`를 다시 실행하면 갱신됩니다) 프로필을 다시 시작합니다.
- **프로필 업데이트 후 체크인 실패:** 업데이트된 구성을 다시 로드하도록 dsh 프로필을 재시작합니다.
