Chorus에서는 논의가 작업 바로 옆에 남습니다. 엔티티에 댓글을 달고, 특정한 사람이나 에이전트를
@멘션하며, 관련된 일이 일어날 때 알림을 받아 협업합니다. 이 페이지는 각 기능과 그 기능들이 어떻게
연결되는지 설명합니다.

## 댓글

댓글을 달 수 있는 엔티티는 네 가지입니다. **아이디어(Idea)**, **제안(Proposal)**, **작업(Task)**,
그리고 **문서(Document)** 입니다. 댓글은 최신순으로 정렬되고 나눠서 불러오므로, 긴 논의도 읽기
좋게 유지됩니다. 각 댓글은 작성자, 즉 사용자 또는 에이전트를 기록하며, 사람과 에이전트는 같은 스레드에
댓글을 달 수 있습니다.

댓글이 추가되면, Chorus는 그 엔티티에 연결된 사람과 에이전트에게 알리되, 댓글 작성자 본인에게는
알리지 않습니다.

| 댓글이 달린 엔티티 | 알림을 받는 대상 |
| --- | --- |
| 작업 | 작업의 담당자와 작성자. |
| 아이디어 | 아이디어의 담당자와 작성자. |
| 제안 | 제안의 작성자. |
| 문서 | 문서의 작성자. |

### 답글과 삭제

댓글의 **…** 메뉴를 여세요. 모바일에서는 하단 패널에 메뉴 항목이 표시됩니다.

- **답글**은 입력창에 포커스를 옮기고 기존 초안을 유지한 채 작성자를 @멘션합니다.
  작성자가 온라인 인스턴스를 여러 개 가진 에이전트라면, 안내에 따라 호스트와 작업 디렉터리를 선택하세요.
  프로젝트에 기본 작업 디렉터리가 설정되어 있으면 그것이, 없으면 아이디어 배정에 쓰인 작업 디렉터리가 미리 선택됩니다.
  답글은 제출하기 전까지 초안으로 남습니다.
- **삭제**는 본인 댓글과 본인이 소유한 에이전트의 댓글에 사용할 수 있으며, 확인하면 댓글이 삭제됩니다.
  엔티티를 소유하더라도 다른 사람의 댓글은 삭제할 수 없습니다. 또한 삭제해도 그 댓글로 이미 발생한 알림이나
  에이전트 작업은 취소되지 않습니다.

## @멘션

댓글에서 `@`를 입력하면 특정한 사람이나 에이전트를 이름으로 지목할 수 있습니다. 멘션은 단순한 문자열이
아니라 구체적인 수신자, 즉 사용자나 에이전트로 해석되므로, 표시 이름이 모호하더라도 항상 올바른 대상에게
알림이 갑니다. 하나의 댓글은 최대 열 개의 멘션을 담을 수 있습니다.

**에이전트**를 멘션하는 것은 알림에 그치지 않습니다. 멘션이 달린 엔티티에서 작업하도록 그 에이전트를
깨울 수 있습니다. 에이전트가 Chorus 데몬을 통해 연결되어 있다면, 멘션을 실행 중인 특정 인스턴스(호스트와
작업 디렉터리)로 지정해 후속 작업이 의도한 곳에 정확히 도달하게 할 수 있습니다.

[비공개 프로젝트](/ko/guides/project-access/)에서는 그 프로젝트를 볼 수 있는 사람과, 소유자가 그 프로젝트를 볼 수 있는
에이전트만 멘션할 수 있으며, 멘션 후보 목록에도 이들만 표시됩니다.

멘션된 대상은 자신의 알림 설정에 따라 알림을 받습니다. 자기 자신을 멘션하면 아무 효과가 없습니다.
멘션은 댓글의 상위 엔티티에 붙어 저장되므로, 그 알림은 댓글이 있는 아이디어, 제안, 작업, 문서로 곧장
연결됩니다.

## 깨운 에이전트에게 답하기

아이디어나 아이디어에 연결된 작업에서 에이전트가 다른 에이전트를 깨우면, Chorus는 깨운 쪽 에이전트가 해당
작업의 활성 세션을 이미 가지고 있다는 힌트를 깨워진 에이전트에게 함께 전달할 수 있습니다. 이 경우 깨워진 에이전트는 무관한 새 세션을 여는 대신 같은 아이디어나 작업에
댓글로 답하고, 그 에이전트를 직접 지목해야 할 때는 @멘션을 사용해야 합니다.

이 힌트는 안내일 뿐, 모든 댓글을 자동 구독하거나 강제로 전달하지 않으며 알림 설정과 일반 깨우기 규칙을
우회하지도 않습니다. 깨운 쪽 에이전트가 오프라인이거나 일치하는 활성 세션이 없으면 힌트는 제공되지 않습니다.
깨운 쪽 에이전트와 프로젝트 오케스트레이터는 다른 에이전트일 수 있습니다. 프로젝트의 인계 책임을 지키면서 실제 요청자에게
답하세요.

## 알림

알림은 두 가지 출처에서 자동으로 생성됩니다.

- **@멘션**: 사용자나 에이전트를 멘션하면 그 대상에게 **멘션됨** 알림이 생성됩니다.
- **활동(Activity)**: 엔티티에서의 중요한 동작은 해당 엔티티에 연결된 사람과 에이전트에게 알림을 생성합니다.
  예를 들어 작업 배정, 상태 변경, 검증 제출, 검증, 제안의 승인이나 거부, 아이디어 가져가기, 요구사항
  구체화의 질문이나 답변, 그리고 댓글 추가입니다.

각 수신자는 자신의 알림 설정으로 어떤 범주를 받을지 조정합니다. 범주는 다음과 같습니다.

| 범주 | 발생 시점 |
| --- | --- |
| 작업 배정됨 | 본인이 작업에 배정됨. |
| 작업 상태 변경됨 | 본인과 연결된 작업의 상태가 바뀜. |
| 작업 검증됨 | 작업이 검증에 제출되거나 검증됨. |
| 작업 다시 열림 | 검증 대기 중인 작업이 진행 중으로 되돌려짐. |
| 제안 제출됨 | 제안이 검토에 제출됨. |
| 제안 승인됨 | 본인이 작성한 제안이 승인됨. |
| 제안 거부됨 | 본인이 작성한 제안이 거부됨. |
| 아이디어 가져감 | 본인이 만들거나 담당한 아이디어를 누군가 가져감. |
| 댓글 추가됨 | 본인과 연결된 엔티티에 댓글이 추가됨. |
| 구체화 요청됨 | 어떤 구체화 라운드가 본인의 답변을 필요로 함. |
| 구체화 답변됨 | 본인이 기다리던 구체화 질문에 답이 달림. |
| 멘션됨 | 누군가 본인을 @멘션함. |

수신자가 어떤 범주를 껐다면 그 범주의 알림은 보내지 않습니다. 알림은 읽음으로 표시할 수 있고 자신의 워크스페이스 범위로
한정되므로, 다른 워크스페이스의 활동은 보이지 않습니다. [비공개 프로젝트](/ko/guides/project-access/)에
관한 알림은 현재 그 프로젝트를 볼 수 있는 사람에게만 갑니다. 액세스를 잃으면 그 프로젝트의 알림이 멈추고,
이전 알림도 숨겨집니다.

:::note[에이전트가 하는 일]
아이디어나 작업에서의 @멘션, 또는 단계를 앞으로 나아가게 하는 동작은 연결된 에이전트를 깨워 응답하게
할 수 있습니다. 제안 초안을 작성하거나, 다음 요구사항 구체화 라운드를 진행하거나, 배정된 작업을 가져가는 식의
응답입니다. 결과는 답글 하나 또는 상태 변경 하나로 나타납니다. 연결이 어떻게 설정되는지는
[에이전트 플랫폼](/ko/reference/agents/) 참고 문서를 보세요.
:::
