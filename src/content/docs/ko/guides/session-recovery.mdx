에이전트가 잘못된 방향으로 가고 있을 때, 하염없이 기다릴 때, 또는 추가 지시가 필요할 때 이 컨트롤을 사용합니다. 이들은 기존 대화에 작용합니다. 새 대화를 만들려면 [원격 에이전트에서 작업 시작](/ko/guides/remote-control/)을 사용하세요.

## 실행 중인 작업 중단하기

1. 실행 중인 대화를 엽니다.
2. 최신 출력을 검토해 중단이 필요한지 확인합니다.
3. **중단**(Interrupt)을 선택합니다.
4. 대화가 실행이 멈췄다고 보고할 때까지 기다립니다.

중단은 먼저 에이전트 프로세스에 정상적으로 멈추라고 요청합니다. 구성된 타임아웃 안에 멈추지 않으면, 데몬이 그 프로세스를 종료합니다.

:::caution[중단은 작업을 되돌리지 않습니다]
중단 전에 완료된 파일, 명령, 코멘트, 외부 작업은 그대로 남습니다. 다른 실행을 시작하기 전에 부분 결과를 검토하세요.
:::

## 부분 결과 살펴보기

재개하기 전에.

- 에이전트의 최종 출력과 오류 세부 정보를 읽습니다.
- 변경된 파일과, 실행 중인 프로세스가 있으면 살펴봅니다.
- 이어 갈지, 수정된 지시를 줄지, 아니면 평소의 버전 관리 워크플로로 부분 변경을 버릴지 결정합니다.

첫 세션이 무엇을 바꿨는지 이해하기 전에는, 같은 디렉터리에 대해 두 번째 세션을 시작하지 마세요.

## 대화 재개하기

대화가 중단된 상태이거나, 크래시 후 복구 가능한 상태일 때.

1. 원래 데몬 연결이 오프라인이면 복구합니다.
2. 같은 대화를 엽니다.
3. 수정 사항이나 빠진 맥락이 있으면 추가합니다.
4. **재개**(Resume)를 선택합니다.

재개는 원래의 에이전트 연결과 작업 디렉터리를 사용합니다. 세션을 다른 컴퓨터나 디렉터리로 옮기지 않습니다. 원래 런타임이 돌아올 수 없다면, 새 세션을 의도적으로 시작하고 이전 시도에서 관련 맥락을 포함하세요.

반복해서 실패하면 [에이전트 연결 문제 해결](/ko/guides/troubleshooting/)을 사용하세요.

## 터미널에서 이어받기

UI 안의 **재개**(Resume) 버튼 대신, 자신의 터미널에서 대화를 이어 갈 수도 있습니다. 대화를 열고, 트랜스크립트 헤더에서 **Copy session ID**를 선택합니다. 이것은 백엔드가 보유한 resume id, 즉 데몬이 재개할 때 에이전트 CLI에 넘기는 바로 그 id를 복사하므로, 수동 재개는 새 대화를 시작하는 대신 같은 대화에 다시 합류합니다.

{/* Screenshot surface: transcript header with the Copy session ID control. */}

대화가 실행되던 작업 디렉터리에서, 복사한 id를 백엔드의 재개 명령에 넘깁니다.

- **Claude Code** — `claude --resume <sessionId>`
- **Codex** — `codex exec resume <thread_id>`
- **Kiro** — `kiro-cli chat --resume-id <sessionId>`

각 백엔드는 자체 id 형식을 가지므로, 복사된 값은 그 백엔드가 받아들이는 형식입니다. 정확한 명령은 각 플랫폼의 참고 페이지를 보세요. [Claude Code](/ko/reference/agents/claude-code/), [Codex](/ko/reference/agents/codex/), [Kiro](/ko/reference/agents/kiro/)입니다.

Chorus는 아이디어마다 하나의 표준 세션을 유지합니다. 아이디어를 직접 작업할 때, 그 session id는 아이디어 자신의 UUID(`sessionId === directIdeaUuid`)이며, 다른 작업 디렉터리로 옮겨 가는 웨이크는 새 대화를 포크하는 대신 이 단일 세션을 다시 가리킵니다. 그래서 마지막에 어디서 실행되었든, 이어받을 대화는 항상 정확히 하나입니다. 전체 모델은 [온라인 에이전트 개요](/ko/guides/online-agents-overview/)를 보세요.
