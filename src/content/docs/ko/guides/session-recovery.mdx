에이전트가 잘못된 방향으로 가고 있거나, 끝없이 기다리고 있거나, 추가 지시가 필요할 때 이 컨트롤을 사용합니다. 이 컨트롤은 기존 대화에 적용됩니다. 새 대화를 만들려면 [원격 에이전트에서 작업 시작](/ko/guides/remote-control/)을 사용하세요.

## 실행 중인 작업 중단하기

1. 실행 중인 대화를 엽니다.
2. 최신 출력을 검토해 중단이 필요한지 확인합니다.
3. **중단**을 선택합니다.
4. 대화에 실행이 멈췄다고 표시될 때까지 기다립니다.

중단은 먼저 에이전트 프로세스에 정상 종료를 요청합니다. 구성된 타임아웃 안에 멈추지 않으면 데몬이 프로세스를 강제로 종료합니다.

:::caution[중단은 작업을 되돌리지 않습니다]
중단 전에 완료된 파일, 명령, 댓글, 외부 작업은 그대로 남습니다. 다른 실행을 시작하기 전에 부분 결과를 검토하세요.
:::

## 실행 중 표시가 사라지지 않을 때

프로세스가 끝났는데 대화가 계속 **실행 중**이라면 해당 대화에서 **중단**을 선택하세요.
활성 실행이 목록에 없어도 이 컨트롤을 사용할 수 있습니다. 중지할 활성 실행이 없으면 Chorus가 턴을 바로 중단됨으로
표시할 수 있고, 활성 실행이 있으면 데몬에 요청을 전달한 뒤 중지 결과를 기다립니다.

Chorus는 턴 종료 보고가 일시적으로 실패하면 다시 보고하며, 에이전트 프로세스가 끝나면 그 프로세스가 시작한
백그라운드 프로세스가 아직 실행 중이더라도 에이전트가 종료된 것으로 처리합니다. 이 중 어느 것도 턴의 실행 시간을 제한하지 않지만,
백엔드별 제한은 여전히 적용됩니다. DeepSeek Harness(`dsh`)는 기본적으로 턴당 30분이며
`CHORUS_DSH_TIMEOUT_MS`로 변경할 수 있습니다.
재개하기 전에 마지막 출력과 남아 있는 프로세스를 확인하세요.

## 부분 결과 살펴보기

재개하기 전에 다음을 확인합니다.

- 에이전트의 최종 출력과 오류 세부 정보를 읽습니다.
- 변경된 파일과 실행 중인 프로세스(있는 경우)를 살펴봅니다.
- 그대로 이어 갈지, 수정한 지시를 줄지, 아니면 평소의 버전 관리 워크플로로 부분 변경을 버릴지 결정합니다.

첫 세션이 무엇을 바꿨는지 파악하기 전에는 같은 디렉터리에서 두 번째 세션을 시작하지 마세요.

## 대화 재개하기

대화가 중단되었거나 크래시 후 복구할 수 있는 상태라면 다음과 같이 합니다.

1. 원래 데몬 연결이 오프라인이면 복구합니다.
2. 같은 대화를 엽니다.
3. 수정 사항이나 빠진 맥락이 있으면 추가합니다.
4. **재개**를 선택합니다.

재개는 원래의 에이전트 연결과 작업 디렉터리를 사용합니다. 세션을 다른 컴퓨터나 디렉터리로 옮기지 않습니다. 원래 런타임을 되살릴 수 없다면 새 세션을 직접 시작하고, 이전 시도의 관련 맥락을 함께 전달하세요.

실패가 반복되면 [에이전트 연결 문제 해결](/ko/guides/troubleshooting/)을 참고하세요.

## 터미널에서 이어받기

UI의 **재개** 버튼 대신 자신의 터미널에서 대화를 이어 갈 수도 있습니다. 대화를 열고 기록 헤더에서 **세션 ID 복사**를 선택합니다. 에이전트 CLI가 재개할 때 쓰는 세션 ID가 복사되므로, 수동으로 재개해도 새 대화가 시작되지 않고 같은 대화로 돌아갑니다.

{/* Screenshot surface: transcript header with the Copy session ID control. */}

대화가 실행되던 작업 디렉터리에서, 복사한 세션 ID를 백엔드의 재개 명령에 넘깁니다.

- **Claude Code** — `claude --resume <sessionId>`
- **Codex** — `codex exec resume <thread_id>`
- **Kiro** — `kiro-cli chat --resume-id <sessionId>`

백엔드마다 ID 형식이 다르며, 복사되는 값은 해당 백엔드가 받아들이는 형식입니다. 정확한 명령은 각 플랫폼의 참고 문서([Claude Code](/ko/reference/agents/claude-code/), [Codex](/ko/reference/agents/codex/), [Kiro](/ko/reference/agents/kiro/))를 확인하세요.

Chorus는 아이디어마다 세션을 하나만 유지합니다. 다른 작업 디렉터리에서 그 아이디어의 작업을 시작하면 Chorus는 새 세션을 만들지 않고 이 세션을 그곳으로 옮깁니다. 따라서 마지막에 어디서 실행되었든 이어받을 대화는 언제나 하나뿐입니다. 전체 구조는 [온라인 에이전트 개요](/ko/guides/online-agents-overview/)를 참고하세요.
