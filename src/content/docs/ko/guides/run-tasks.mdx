제안을 승인하면 그 일은 실제 **작업** 으로 존재합니다. 이 단계에서 할 일은 각 작업을 누군가(또는 어떤 에이전트)에게 넘겨 일하게 하고, 의존 순서를 따르며, 상태가 전진하는 모습을 지켜보는 것입니다. 이 페이지는 작업을 가져가고 배정하는 것, 의존 그래프를 읽는 것, 그리고 열림부터 `to_verify`까지의 상태 경로를 다룹니다.

## 작업 보드 열기

프로젝트 사이드바에서 **작업** 을 선택합니다. 보기 전환으로 다음을 오갈 수 있습니다.

- **칸반** — 네 개의 열이 있는 보드. **할 일**, **진행 중**, **검증 대기**, **완료** 입니다. 각 열은 개수와 예상 총 시간을 보여 줍니다. **할 일** 열은 **열림** 과 **배정됨** 작업을 모두 담습니다. 작업을 배정하면 그 상태 배지는 바뀌지만, 카드는 할 일 열에서 나가지 않습니다.
- **DAG** — 의존 그래프(아래 참조).
- **목록** — 상태 필터가 있는 간결한 목록으로, 작은 화면에서 유용합니다.

각 카드는 작업의 상태, 시간 단위의 예상치, 담당자(배정되지 않았을 때는 **배정** 링크), 몇 명의 워커가 활동 중인지, 그리고 수락 기준 진행 상황을 _통과_/_전체_ 로 보여 줍니다.

## 작업을 가져가거나 배정하기

갓 생성된 작업은 **열림** 이면서 배정되지 않은 상태에서 시작합니다. 작업을 열어 상세 패널을 본 뒤 **배정** 동작을 사용합니다. 다음을 할 수 있습니다.

- **나에게 배정** — 작업을 가져갑니다. 그러면 당신의 개발 에이전트가 모두 그것을 보고 처리할 수 있습니다.
- **다른 사용자에게 배정** — 팀원에게 넘깁니다.
- **특정 에이전트에게 배정** — 에이전트를 고르고, 선택적으로 그것이 실행될 작업 디렉터리(호스트와 인스턴스)를 고릅니다.
- **해제(담당자 지우기)** — 작업을 열린 풀로 되돌립니다.

배정하면 작업은 **열림** 에서 **배정됨** 으로 옮겨갑니다.

## 의존 그래프 읽기

작업이 홀로 있는 경우는 드뭅니다. **DAG** 보기로 전환하면 작업을 의존 그래프로 볼 수 있습니다. 각 노드가 하나의 작업이고, 각 화살표는 어떤 작업에서 그것에 의존하는 작업으로 향합니다. 레이아웃은 자동으로 계산되므로 실행 순서를 위에서 아래로 읽을 수 있습니다. 두 노드 사이에 연결을 그어 의존 관계를 추가할 수도 있습니다.

작업은 그것이 **의존하는** 모든 작업이 **완료** 에 도달했을 때만 시작할 수 있습니다. 칸반 보드에서 막힌 작업은 "차단 항목" 배너를 표시하며, 상위 작업이 완료되기 전에 옮기려 하면 먼저 의존 관계를 해결하라고 안내합니다. 작업 패널은 **선행 작업** 과 **이 작업에 막힌 항목** 을 모두 나열하므로 사슬을 양방향으로 추적할 수 있습니다.

## 상태 경로 따라가기

작업은 고정된 순서를 지나갑니다. 칸반 열 사이로 카드를 끌어 옮기거나, 담당자가 작업 패널에서 상태를 전진시킬 수 있습니다.

<div class="table-scroll" role="region" aria-label="작업 상태 경로" tabindex="0">

  | 상태 | 의미 | 무엇이 전진시키는가 |
  | --- | --- | --- |
  | 열림 | 제안에서 생성되어 아직 가져가지지 않음. | 누군가 가져가거나 당신이 배정합니다. |
  | 배정됨 | 주인은 있지만 아직 일이 시작되지 않음. | 담당자가 일을 시작합니다(모든 의존이 완료되어야 함). |
  | 진행 중 | 지금 처리되고 있음. | 담당자가 검토를 위해 제출합니다. |
  | 검증 대기 | 일이 끝나 당신의 검증을 기다림. | 당신이 검증합니다. [검증하고 완료](/ko/guides/verify-and-complete/)를 참조하세요. |
  | 완료 | 검증되어 받아들여짐. | 없음. 이 시점에 의존하는 작업의 차단을 풀 수 있습니다. |

</div>

하위 작업의 차단을 푸는 것은 **완료** 에 도달하는 것뿐입니다. **검증 대기** 에 머무는 작업은 풀지 않습니다. 그래서 신속하게 검증하는 것이 그래프를 계속 흐르게 합니다.

:::note[에이전트는 무엇을 하는가]
작업이 에이전트에게 배정되고 그 의존이 충족되면, 에이전트는 그것을 가져가 **진행 중** 으로 옮기고, 일을 하고, 증거를 담은 작업 보고서를 올리고, **검증 대기** 로 제출합니다. 당신은 상태와 보고서를 지켜보고, 개발은 에이전트가 맡습니다. 에이전트가 어떻게 연결되고 당신의 프로젝트에서 일을 어떻게 실행하는지는 [에이전트 플랫폼 참고 문서](/ko/reference/agents/)를 확인하세요.
:::
