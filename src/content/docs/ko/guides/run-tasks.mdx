제안을 승인하면 그 일은 실제 **작업**이 됩니다. 이 단계에서는 각 작업을 처리할 사람이나 에이전트에게 넘기고, 의존 순서를 따르며, 상태가 진행되는 것을 지켜봅니다. 이 페이지에서는 작업 가져가기와 배정, 의존 그래프 읽기, 그리고 **열림**부터 **검증 대기**까지의 상태 경로를 다룹니다.

## 작업 보드 열기

프로젝트 사이드바에서 **작업**을 선택합니다. 보기 전환으로 다음을 오갈 수 있습니다.

- **칸반** — 네 개의 열이 있는 보드. **할 일**, **진행 중**, **검증 대기**, **완료**입니다. 각 열에는 작업 수와 예상 시간 합계가 표시됩니다. **할 일** 열에는 **열림**과 **배정됨** 작업이 모두 들어갑니다. 작업을 배정하면 상태 배지는 바뀌지만 카드는 할 일 열에 그대로 남습니다.
- **DAG** — 의존 그래프(아래 참조).
- **목록** — 상태 필터가 있는 간결한 목록으로, 작은 화면에서 유용합니다.

각 카드에는 작업의 상태, 시간 단위 예상치, 담당자(배정되지 않았으면 **배정** 링크), 그 작업에서 활동 중인 워커 수, 그리고 *통과*/*전체* 형식의 수락 기준 진행 상황이 표시됩니다.

## 작업을 가져가거나 배정하기

제안에서 새로 생성된 작업은 **열림** 상태이며 배정되지 않은 채로 시작합니다. 작업을 열어 상세 패널을 표시한 뒤 **배정** 동작을 사용합니다. 다음을 할 수 있습니다.

- **나에게 배정** — 작업을 가져갑니다. 그러면 내 개발 에이전트 모두가 그 작업을 보고 처리할 수 있습니다.
- **다른 사용자에게 배정** — 팀원에게 넘깁니다.
- **특정 에이전트에게 배정** — 에이전트를 고르고, 선택적으로 에이전트가 실행될 작업 디렉터리(호스트와 인스턴스)도 고릅니다.
- **해제 (담당자 지우기)** — 작업을 누구나 가져갈 수 있는 상태로 되돌립니다.

배정하면 작업은 **열림**에서 **배정됨**으로 옮겨갑니다.

## 의존 그래프 읽기

작업이 단독으로 있는 경우는 드뭅니다. **DAG** 보기로 전환하면 작업을 의존 그래프로 볼 수 있습니다. 각 노드는 작업 하나이고, 각 화살표는 어떤 작업에서 그 작업에 의존하는 작업을 가리킵니다. 레이아웃은 자동으로 계산되므로 실행 순서를 위에서 아래로 읽을 수 있습니다. 두 노드 사이에 연결을 그어 의존 관계를 추가할 수도 있습니다.

작업은 **의존하는** 작업이 모두 **완료**에 도달해야 시작할 수 있습니다. 칸반 보드에서 막힌 작업에는 "차단 항목" 배너가 표시되며, 선행 작업이 완료되기 전에 옮기려 하면 먼저 의존 관계를 해결하라는 안내가 나옵니다. 작업 패널에는 **선행 작업**과 **이 작업에 막힌 항목**이 모두 나열되므로 의존 사슬을 양방향으로 추적할 수 있습니다.

## 상태 경로 따라가기

작업은 정해진 순서대로 상태가 바뀝니다. 칸반 열 사이로 카드를 끌어 옮길 수도 있고, 담당자가 작업 패널에서 상태를 다음 단계로 바꿀 수도 있습니다.

<div class="table-scroll" role="region" aria-label="작업 상태 경로" tabindex="0">

  | 상태 | 의미 | 다음 상태로 넘어가는 조건 |
  | --- | --- | --- |
  | 열림 | 제안에서 생성되어 아직 아무도 가져가지 않음. | 누군가 가져가거나 사용자가 배정합니다. |
  | 배정됨 | 담당자는 있지만 아직 일이 시작되지 않음. | 담당자가 일을 시작합니다(의존하는 작업이 모두 완료되어야 함). |
  | 진행 중 | 지금 처리되고 있음. | 담당자가 검토를 위해 제출합니다. |
  | 검증 대기 | 일이 끝나 사용자의 검증을 기다림. | 사용자가 검증합니다. [검증과 완료](/ko/guides/verify-and-complete/)를 참조하세요. |
  | 완료 | 검증되어 받아들여짐. | 없음. 이제 이 작업에 의존하는 작업의 차단이 풀릴 수 있습니다. |

</div>

후속 작업의 차단은 **완료**에 도달해야만 풀립니다. **검증 대기**에 머물러 있는 작업으로는 풀리지 않습니다. 그래서 빨리 검증해야 그래프가 막힘없이 진행됩니다.

:::note[에이전트가 하는 일]
작업이 에이전트에게 배정되고 의존 조건이 충족되면, 에이전트가 작업을 가져가 **진행 중**으로 옮기고, 일을 한 뒤, 증거를 담은 작업 보고서를 올리고 **검증 대기**로 제출합니다. 사용자는 상태와 보고서를 지켜보고, 개발은 에이전트가 맡습니다. 에이전트가 어떻게 연결되고 프로젝트에서 일을 어떻게 실행하는지는 [에이전트 플랫폼 참고 문서](/ko/reference/agents/)를 확인하세요.
:::
