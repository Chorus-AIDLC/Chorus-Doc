Chorus는 **AI-DLC(AI 기반 개발 수명 주기)** 위에서 동작합니다. AI-DLC는 모든 일을 다듬어지지 않은 아이디어에서 검증된 결과까지 이끄는 고정된 파이프라인입니다. 사용자와 AI 에이전트는 같은 파이프라인을 공유하지만, 맡은 역할은 다릅니다. 이 페이지는 각자의 역할과 일이 거치는 단계를 설명한 뒤, 단계별 가이드로 안내합니다.

## 뒤집힌 대화

대부분의 AI 도구는 한 방향입니다. 사람이 프롬프트를 쓰면 AI가 그것을 실행합니다. Chorus는 그 방향을 뒤집습니다.

**AI가 제안하고, 사람이 검증합니다.** 에이전트는 아이디어를 먼저 질문으로 풀어낸 다음, 설계·명세 문서와 작업 목록으로 이루어진 구체적인 제안으로 만듭니다. 사용자가 그 제안을 읽고 승인하기 전까지는 아무것도 만들어지지 않으며, 결과를 수락 기준에 비추어 확인하기 전까지는 아무것도 완료되지 않습니다. 모든 관문에서 결정은 사용자가 내리고, 그 사이의 초안 작성과 실행은 에이전트가 맡습니다.

이것이 "뒤집힌 대화"입니다. *사람이 프롬프트 → AI가 실행*이 아니라, *AI가 제안 → 사람이 검증*. 아래의 각 단계가 곧 사용자가 결정을 내리는 관문입니다.

## 파이프라인

일은 하나의 경로를 따라 흐릅니다.

**아이디어 → 제안 → 문서 + 작업 → 실행 → 검증 → 완료.**

워크스페이스는 한 번만 설정하면, 이후 모든 요청이 이 경로를 지나갑니다. 아래 표는 사용자의 관점에서 각 단계를 설명하고, 그 가이드로 연결합니다.

<div class="table-scroll" role="region" aria-label="AI-DLC 파이프라인 단계" tabindex="0">

  | 단계 | 사용자가 하는 일 | 가이드 |
  | --- | --- | --- |
  | 프로젝트 설정 | 프로젝트를 만들고, 작업 디렉터리를 지정한 뒤 엽니다. 아래의 모든 단계는 프로젝트 안에서 이루어집니다. | [프로젝트 생성](/ko/guides/create-a-project/) |
  | 아이디어 | 원하는 것을 아이디어로 기록합니다. 에이전트는 양쪽의 이해가 일치할 때까지 요구사항 구체화 라운드, 즉 짧은 일문일답을 진행합니다. 그런 다음 사용자가 내용을 확인하고 확정합니다. | [아이디어 기록](/ko/guides/capture-an-idea/) |
  | 제안 | 에이전트가 제안을 작성해 제출합니다. 사용자는 그 문서와 작업 초안을 읽고 승인하거나 거부합니다. 승인하면 초안에서 **문서**와 **작업**이 생성됩니다. | [제안 검토](/ko/guides/review-a-proposal/) |
  | 실행 | 작업은 에이전트가 가져가거나 배정받아 하나씩 진행됩니다. 각 작업이 검토를 향해 나아가는 동안, 사용자는 작업의 상태와 의존 그래프를 지켜봅니다. | [작업 실행](/ko/guides/run-tasks/) |
  | 검증 → 완료 | 각 작업을 수락 기준에 비추어 확인하고 검증합니다. 일이 검증되면 아이디어가 완료되고, 그 보고서를 읽을 수 있습니다. | [검증과 완료](/ko/guides/verify-and-complete/) |

</div>

이 순서대로 가이드를 읽어 나가면, 파이프라인을 벗어나지 않고 빈 워크스페이스에서 검증되고 완료된 아이디어까지 도달할 수 있습니다.

:::note[에이전트가 하는 일]
에이전트는 모든 단계에서 사용자의 상대역입니다. 요구사항 구체화 질문을 던지고, 제안을 작성하고, 승인된 작업을 실행하고, 검토할 수 있도록 근거를 보고합니다. Chorus는 각 동작의 효과, 즉 새 요구사항 구체화 라운드, 제출된 제안, **검증 대기** 상태의 작업을 보여 주고 사용자의 결정을 기다립니다. 에이전트가 어떻게 연결되고 무엇을 할 수 있는지는 [에이전트 플랫폼 참고 문서](/ko/reference/agents/)를 확인하세요.
:::
