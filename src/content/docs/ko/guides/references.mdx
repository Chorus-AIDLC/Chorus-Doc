Chorus에서 하는 일은 대개 외부 자료에 근거합니다. 따르고 있는 공식 문서, 본보기로 삼는 저장소, 문제를 제기한 이슈 스레드, 또는 접근 방식을 떠올리게 한 글 등입니다. **참고 자료**는 그 근거를 링크로 담으며, URL, 제목, 그리고 왜 중요한지 적는 메모(선택)로 이루어집니다. Chorus는 그 링크와 메모만 저장합니다. URL 뒤의 페이지를 가져오거나, 내려받거나, 스냅숏하지 않습니다.

참고 자료는 **아이디어**, **제안**, 또는 **작업**에 첨부되어, 근거가 그것이 뒷받침하는 일 바로 옆에 놓입니다. 에이전트가 작업을 넘겨받으면 첨부한 참고 자료가 작업과 함께 따라갑니다. 에이전트가 계획을 제안할 때도 참고한 출처를 첨부해 사용자가 확인할 수 있게 합니다.

## 참고 자료 추가하기

아이디어·제안·작업을 열고 **참고 자료** 섹션(제안 패널에서는 카드, 작업과 아이디어에서는 제목이 붙은 섹션)을 찾습니다. **참고 자료 추가**를 선택하고 다음을 채웁니다.

- **유형** — 네 종류 중 하나로, 각각 고유한 아이콘과 배지로 표시됩니다.
  - **문서** — 공식 문서.
  - **저장소** — 참고 구현체 또는 코드베이스.
  - **이슈 / PR** — 이슈 또는 pull request 스레드.
  - **논문 / 블로그** — 논문 또는 블로그 글.
- **URL** — 웹 링크(`http://` 또는 `https://`, 로컬 파일은 사용할 수 없음).
- **제목** — 참고 자료의 짧은 이름.
- **메모** — 선택 사항. 참고 자료가 왜 관련 있는지 한 문장으로 간결하게 적습니다. 처음 두 줄만 표시되므로 짧게 쓰세요. 전체 텍스트는 마우스를 올리면 볼 수 있습니다.

추가한 참고 자료는 곧바로 섹션에 나타납니다. 어느 참고 자료든 같은 자리에서 편집하거나 삭제할 수 있습니다. 삭제하면 링크가 Chorus에서 제거되며 되돌릴 수 없습니다.

## 인라인 인용 읽기

설명·문서·댓글에서는 주장하는 바로 그 자리에 참고 자료를 인용할 수 있습니다. 인용은 본문 안에 **[1]** 같은 작은 대괄호 숫자로 나타납니다.

- **마우스를 올리거나 포커스하면** 참고 자료의 현재 제목, 유형, URL, 메모를 볼 수 있습니다. 본문이 작성된 뒤 참고 자료가 편집되었다면 최신 버전이 표시됩니다.
- **선택하면** 출처가 새 탭에서 열립니다.
- **회색** 인용은 열 수 없습니다. 마우스를 올리거나 포커스하면 그 이유를 볼 수 있습니다. 참고 자료가 더 이상 존재하지 않거나(**근거를 찾을 수 없습니다**), 상세 정보를 아직 불러오는 중이거나, 불러오지 못한 경우입니다. 불러오지 못했다면 다음에 마우스를 올리거나 포커스할 때 Chorus가 다시 시도합니다.

인용은 지금 읽고 있는 항목에 첨부된 것뿐 아니라, 접근할 수 있는 어떤 참고 자료든 가리킬 수 있습니다. [아이디어](/ko/guides/capture-an-idea/#개발-전에-리서치-요청하기)에 대한 리서치도 이 방식으로 각 발견 사항을 출처와 연결합니다.

## 에이전트는 참고 자료를 어떻게 사용하는가

에이전트도 사람과 같은 방식으로 참고 자료를 첨부합니다. 그래서 제안에 처음부터 출처가 첨부되어 있을 수 있습니다. `document:write` 권한을 가진 에이전트는 세 가지 도구(`chorus_add_reference`, `chorus_update_reference`, `chorus_remove_reference`)를 사용할 수 있으며, 아이디어, 제안, 작업 묶음을 만들 때 인라인으로 참고 자료를 첨부할 수도 있습니다. 엔티티를 읽는 사람은 누구든 그 참고 자료를 인라인으로 볼 수 있으며, 특별한 권한은 필요하지 않습니다.

에이전트는 인용을 참고 자료 ID를 가리키는 평범한 Markdown 링크(예: `[1](ref:<reference-uuid>)`)로 쓰며, ID는 참고 자료를 첨부하거나 읽을 때 Chorus가 돌려주는 값을 사용합니다. 어떤 참고 자료와도 맞지 않는 ID는 **근거를 찾을 수 없습니다**로 표시되므로, 에이전트는 먼저 참고 자료를 첨부하거나 조회해야 하며, ID를 지어내서는 안 됩니다.

에이전트가 출처를 인용하는 습관을 들이도록 해 두면 좋습니다. 대상 API 문서를 직접 링크한 제안은 근거 없이 믿어 달라는 제안보다 훨씬 검증하기 쉽습니다. 이 도구에 필요한 권한이 전체 권한 체계에서 어떤 위치인지는 [인증 참고 문서](/ko/reference/authentication/)를, 도구 자체는 [MCP 도구 참고 문서](/ko/reference/mcp-tools/)를 확인하세요.
