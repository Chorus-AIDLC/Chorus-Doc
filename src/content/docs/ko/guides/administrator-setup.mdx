Chorus는 직접 관리하지만 에이전트를 실행하는 컴퓨터는 다른 사람이 운영한다면 이 가이드를 참고하세요. 자신의 컴퓨터를 연결한다면 앱 안의 **설정 가이드**가 대개 더 빠릅니다.

## 인증 정보 만들기

1. **설정**(Settings)을 열고 **에이전트**(Agents)로 이동합니다.
2. **API 키 만들기**(Create API Key)를 선택합니다.
3. 에이전트와 그 소유자 또는 컴퓨터를 식별할 수 있는 이름을 입력합니다.
4. 에이전트가 수행할 작업에 가장 가까운 프리셋을 선택합니다.
5. 개별 권한을 검토하고, 에이전트에 필요 없는 것은 제거합니다.
6. 키를 만들고 바로 안전한 곳에 보관합니다.

구현 작업에는 **개발자**(Developer) 프리셋으로 시작하세요. 제안, 문서, 프로젝트, 관리 액세스는 에이전트에 배정된 워크플로가 필요로 할 때만 추가합니다.

## 로컬 워크스페이스 사용자 관리하기

로컬 인증 워크스페이스에서는 비밀번호를 설정한 활성 로컬 **워크스페이스 관리자**로 로그인해 사이드바의 **설정** 아래에 있는 **워크스페이스 사용자**를 엽니다. 일반 사용자, OIDC 사용자, Default Auth 사용자 및 에이전트는 이 관리 기능을 사용할 수 없습니다. 에이전트의 관리자 권한 프리셋은 워크스페이스 관리자 역할과 다릅니다. 슈퍼 관리자는 워크스페이스와 초기 관리자를 만들지만 이 페이지에서 일상적인 사용자 관리를 하지 않습니다.

1. **사용자 초대**를 선택하고 사용자 이름과 이메일을 입력합니다. 표시 이름은 선택 사항이며, 필요할 때만 워크스페이스 관리자 역할을 부여합니다.
2. 사용자 이름은 ASCII 영문자, 숫자, 마침표, 밑줄, 하이픈으로 3~64자이며 영문자나 숫자로 시작하고 `@`를 포함하지 않아야 합니다. 사용자 이름과 이메일은 앞뒤 공백이 제거되고 소문자로 변환되며, 배포 전체가 아닌 이 워크스페이스 안에서만 고유해야 합니다.
3. 결과에 표시된 초대 링크를 복사해 비공개 채널로 공유합니다. 발급 시에만 표시되며 24시간 동안 한 번만 사용할 수 있습니다. 초대 이메일은 자동 발송되지 않습니다.
4. 초대받은 사용자가 직접 비밀번호를 설정한 뒤 별도로 로그인합니다. 상태 변경만으로 비밀번호 없는 초대를 활성화할 수 없습니다.

목록은 **초대됨**, **활성**, **비활성화됨** 계정을 구분합니다. 사용자 이름·이메일·이름 편집, 관리자 역할 부여·회수, 비활성화·재활성화, 제거, 초대 재발급, 활성 사용자용 비밀번호 재설정 링크 발급이 가능합니다. 비밀번호를 설정하지 않았던 계정을 재활성화하면 초대 상태로 돌아가며 새 초대가 발급됩니다.

계정 편집은 기존 세션과 이전 초대·재설정 링크를 무효화합니다. 초대나 재설정 링크를 재발급해도 세션과 이전 링크가 무효화됩니다. 초대 중인 계정에 새 링크가 반환되면 다시 공유하세요. 재설정 완료 후 사용자는 다시 로그인해야 합니다. 비밀번호를 재설정해도 소유한 에이전트 키는 유지되지만 소유자를 비활성화하거나 제거하면 해당 키로 인증할 수 없습니다.

마지막 유효 워크스페이스 관리자를 제거·비활성화·강등할 수 없습니다. 아직 수락하지 않은 초대는 활성 대체 관리자가 아닙니다. 제거해도 과거 작성자 표시와 소유권은 기존 ID에 남습니다. 같은 사용자 이름이나 이메일로 재초대하면 새 ID가 생성되며 이전 작업, 권한, 세션 또는 에이전트 키를 상속하지 않습니다.

워크스페이스 생성과 초기 관리자 복구는 [인증 설정](/ko/guides/authentication-setup/)을 참고하세요. 사용자는 [계정 설정](/ko/guides/account-and-workspace/)에서 자신의 표시 이름과 아바타를 편집할 수 있습니다.

## 운영자에게 필요한 것 전달하기

승인된 보안 채널로 다음 정보를 보냅니다.

- Chorus URL.
- 에이전트 이름과 API 키.
- 선택한 플랫폼(예: Claude Code, Codex, Kiro).
- 에이전트가 작업해도 되는 디렉터리.
- 부여한 권한.

실제 API 키를 티켓, 채팅방, 스크린샷, 셸 명령, 소스 저장소에 두지 마세요.

## 액세스 확인하기

운영자에게 [에이전트 런타임 연결](/ko/guides/operator-onboarding/)의 단계를 따르도록 요청합니다. 운영자가 마치면 다음을 확인합니다.

1. **설정 → 에이전트**(Settings → Agents)를 엽니다.
2. 해당 에이전트를 찾아 연결 세부 정보를 엽니다.
3. 상태가 **온라인**(Online)인지 확인합니다.
4. 백엔드, 호스트, 작업 디렉터리가 의도한 컴퓨터와 일치하는지 확인합니다.

연결이 온라인이 되지 않으면 [에이전트 연결 문제 해결](/ko/guides/troubleshooting/)을 참고하세요. 더 이상 사용하지 않는 인증 정보는 폐기합니다. 특히 컴퓨터나 운영자가 바뀐 뒤에는 잊지 마세요.
