既定では、ワークスペースの全員がすべてのプロジェクトを閲覧し、作業できます。一部の仕事を少人数のチームにとどめたいときは、プロジェクト、あるいはプロジェクトグループ全体を **非公開** にし、誰にどのレベルのアクセスを与えるかを選びます。このガイドでは、この二つのレベルと、それらがどう組み合わさるかを説明します。

## 公開と非公開

すべてのプロジェクトとプロジェクトグループは、**公開** か **非公開** のどちらかです。

- **公開** — ワークスペースの全員（とその人が所有するエージェント）が閲覧できます。公開プロジェクトでは、全員がその着想・提案・文書・課題を作成・編集することもできます。
- **非公開** — メンバー（とそのメンバーが所有するエージェント）だけが閲覧できます。それ以外の人にとっては存在しないのと同じで、プロジェクト一覧、サイドバー、検索、ダッシュボードのいずれにも現れず、そこへのリンクを開いても「ページが見つからない」という旨のメッセージが表示されます。

新しいプロジェクトとグループは、特に指定しない限り公開になります（非公開グループの中の新しいプロジェクトは常に非公開です）。非公開アクセスが導入される前に作成されたプロジェクトは公開のままです。

**プロジェクト** ページとプロジェクトの概要では、非公開プロジェクトに **非公開プロジェクト** バッジが付きます。非公開グループは名前の横に鍵が表示され（カーソルを合わせると説明が出ます）、サイドバーでも非公開プロジェクトの横に同じ鍵が表示されます。

## ロール

非公開プロジェクトやグループのメンバーは、次の三つのロールのいずれかを持ちます。

| ロール | 許可されること |
| --- | --- |
| **閲覧者** | コメントを含め、プロジェクト内のすべてを読めます。何かを作成・編集すること、コメントを投稿すること、要件詳細化の質問に回答すること、仕事を担当することはできません。 |
| **編集者** | 閲覧者ができることすべてに加え、着想・提案・文書・課題の作成と編集、コメント、仕事の担当、提案の承認、課題の検証ができます。 |
| **管理者** | 編集者ができることすべてに加え、公開範囲の変更、メンバーの管理、そして（非公開プロジェクトでは）設定の編集、移動、削除ができます。 |

**公開** プロジェクトには閲覧者はいません。全員が少なくとも編集者として作業し、一般設定、グループ間の移動、削除も全員に開かれたままです。プロジェクトを非公開にしたりメンバーを管理したりできるのは管理者だけです。

プロジェクトを作成した人がその管理者になります。非公開アクセスが導入される前に作成されたプロジェクトでは、ワークスペースに最初に参加したユーザーが管理者です。

閲覧者には、プロジェクトの上部に **このプロジェクトは閲覧のみ可能です。変更するにはプロジェクト管理者に編集者権限を依頼してください。** というバナーが表示されます。**新しい着想** など何かを変更するボタンは非表示または無効になり、ボード上で課題をドラッグすることもできません。

## プロジェクトを非公開にする

プロジェクトを作成するとき、**新規プロジェクト** ダイアログには **公開範囲** の選択肢があります。**公開**（社内の全員がこのプロジェクトを閲覧・編集できます）か **非公開**（一覧に登録されたメンバーとそのエージェントのみがこのプロジェクトにアクセスできます）です。どちらを選んでも、あなたがその管理者になります。[プロジェクトを作成](/ja/guides/create-a-project/)を参照してください。

既存のプロジェクトを変更するには、次のようにします。

1. プロジェクトを開き、概要の右上にある **設定** を選びます。**プロジェクト設定** ダイアログが開くので、**アクセス** タブを選びます。
2. **公開範囲** で **公開** か **非公開** を選びます。
3. Chorus は確認を求め、何人がアクセス権を得るか失うかをまとめた **アクセス権の変更** を表示します。**公開範囲を変更** を選びます。プロジェクトを非公開にすると、メンバーでない人は全員ただちにアクセスできなくなります。公開にすると、ワークスペース全体に開かれます。

非公開グループの中のプロジェクトは公開にできません。

非公開プロジェクトを公開にしてもメンバーは保持されるため、あとでメンバー一覧を作り直さずに非公開に戻せます。

## メンバーを管理する

メンバーを変更できるのは管理者だけです。それ以外の人には一覧と、**公開範囲の変更やメンバー管理はプロジェクト管理者のみが行えます。** という注記が表示されます。**プロジェクト設定 → アクセス** では次のことができます。

- **メンバーを追加** — **ユーザーを選択** を選び、名前またはメールで検索し、ロール（既定は編集者）を選んで **追加** を選びます。
- **ロールを変更** — メンバーの行で別のロールを選びます。
- **削除** — メンバーの行のゴミ箱ボタンを選びます。

プロジェクトには常に少なくとも一人の管理者が残るため、Chorus は最後の管理者の削除や降格を拒否します。変更はすべてただちに反映されます。削除されたメンバーにはそのプロジェクトのライブ更新がすぐに届かなくなり、次に一覧を読み込んだときにはプロジェクトが一覧から消え、開こうとすると「ページが見つからない」という旨のメッセージが表示されます。

### エージェントは所有者に従う

エージェント自体がメンバーになることはありません。エージェントがプロジェクトで閲覧・実行できることは、その所有者ができることとまったく同じで、そのうえでエージェント自身の権限も適用されます。所有者のいないエージェントは公開プロジェクトでしか作業できません。エージェントに非公開プロジェクトへのアクセスを与えるには、その所有者を追加してください。

### メンションと割り当て

非公開プロジェクトでは、そのプロジェクトを閲覧できる人（とそのエージェント）にしか @メンションも仕事の割り当てもできません。担当者には少なくとも編集者のロールが必要です。プロジェクト外の人には、たとえプロジェクトが非公開になる前にそこで何かを作成したり割り当てられたりしていても、そのプロジェクトについての通知は届きません。

## 非公開プロジェクトグループ

プロジェクトグループも非公開にできるため、多くのプロジェクトのアクセスを一か所で管理できます。

- **グループのロールは、グループ内のすべてのプロジェクトにリアルタイムで適用されます。** グループの編集者は、そのグループの各非公開プロジェクトで編集者です。グループメンバーを変更または削除すると、すべてのプロジェクトにただちに反映されます。
- **プロジェクトはアクセスを追加できますが、取り上げることはできません。** 一つのプロジェクトだけで誰かにより高いロールを与えたり、グループ外の人を招き入れたりできます。その人の実効ロールは、グループのロールとプロジェクトのロールのうち高いほうです。グループに由来するロールを、プロジェクト側で下げたり削除したりすることはできません。
- **グループの管理者は、グループ内のすべてのプロジェクトの管理者です。** グループが公開でも非公開でも同じです。
- **非公開グループには非公開プロジェクトしか含められません。** 非公開グループの中で作成したプロジェクトは非公開になり、グループのロールを継承します。作成者にはそのプロジェクトの管理者ロールも付与されます。

プロジェクトの **アクセス** タブでは、各メンバーのロールの由来（**グループから継承**、**プロジェクトの直接権限**、**直接権限＋継承**）と、実際に適用されるロール（**有効**）が表示されます。継承されたロールしか持たないメンバーはそこでは変更も削除もできず、直接のロールを継承されたロールより低く設定することもできません。継承されたロールはグループ側で変更してください。

グループを管理するには、**プロジェクト** ページでそのカードの **ダッシュボードを表示** を選び、続いて **グループを管理** を選びます。グループの管理者には、ダイアログにグループの名前と説明、**公開範囲**、**メンバー**（追加や変更はプロジェクトと同じ手順です）、そして **このグループを削除** が表示されます。公開グループでは誰でも **グループを管理** を開いて名前と説明を編集できますが、公開範囲やメンバーを変更できるのはグループの管理者だけです。非公開グループでは、それ以外のグループメンバーには代わりに **メンバーを表示** が表示され、メンバーの一覧を読み取り専用で確認できます。明示的な管理者のいないグループは、ワークスペースに最初に参加したユーザーが管理し、**自動管理者** と表示されます。明示的な管理者を追加すると、それに置き換わります。

### 一つのプロジェクトにだけアクセスできる人

非公開グループ内の一つのプロジェクトについてだけ、グループメンバーにしないままロールを与えることができます。その人にはグループの名前と説明、そして自分がアクセスできるプロジェクトだけが見えます。件数、ダッシュボード、検索にはグループのそれ以外のものは何も表示されず、グループのメンバーを見ることも、そのグループにプロジェクトを作成することもできません。

### グループを非公開または公開にする

- **公開 → 非公開**：グループ内のすべての公開プロジェクトが非公開になり、グループのロールを継承します。既存のプロジェクトメンバーは保持されます。
- **非公開 → 公開**：グループは全員から見つけられるようになりますが、そのプロジェクトは現在の公開範囲とメンバーを保ちます。非公開のものが公開されることはありません。

どちらの変更の前にも、Chorus は **アクセス権の変更** のまとめ（何人がアクセス権を得るか失うか、何人の権限が上がるか下がるか、何件のプロジェクトに影響があるか）を表示します。それが意図どおりの場合にだけ **公開範囲を変更** を選んでください。確定する前にアクセス権が変わった場合は、Chorus が更新されたまとめを表示するので、内容を確認してもう一度確定してください。

## グループ間でプロジェクトを移動する

プロジェクトを移動するには、**プロジェクト** ページでプロジェクトを別のグループか **未分類** へドラッグします。Chorus は **プロジェクトを別のグループへ移動しますか？** と尋ね、グループのロールはグループに従うため、同じ **アクセス権の変更** のまとめを表示します。進めるには **移動を確定** を選びます。

非公開プロジェクトを移動する場合や、任意のプロジェクトを非公開グループへ、または非公開グループから移動する場合は、移動元のグループ（未分類のプロジェクトであればそのプロジェクト）と移動先のグループの両方の管理者である必要があります。非公開グループへ移動した公開プロジェクトは非公開になります。

プロジェクトのグループのロールは、そのプロジェクトが属しているグループから決まります。別のグループへ移動すると、元のグループのロールは適用されなくなり、代わりに新しいグループのロールが適用されます。プロジェクトを **未分類** へ移動すると、全員がその時点で持っていたアクセス権を保ちます。グループのロールはプロジェクトへコピーされ、非公開プロジェクトは少なくとも一人の管理者を持つ非公開のまま残ります。誤って何かが公開されることはありません。グループを削除するときに **N 件のプロジェクトを未分類へ移動** を選んだ場合も同じです。もう一つの選択肢である **N 件のプロジェクトを完全に削除** を選ぶと、それらは削除されます。
