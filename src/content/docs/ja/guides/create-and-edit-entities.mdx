Chorus は通常、[反転した対話](/ja/guides/ai-dlc-workflow/)の上で動きます。エージェントが提案し、あなたが検証します。しかし、着想・課題・提案のどれにも **手動の入口** があります。着想や課題、提案全体を手で作成できるほか、既存のものを編集・移動・削除したり、親を付け替えたりもできます。このページではこうした手動の操作を扱います。作成したものがその後たどるライフサイクルについては、ここでは繰り返さず各段階のガイドへリンクします。

## 着想を手動で作成する

着想はプロジェクトの **概要** にあるトラッカーで管理します。**新しい着想** を選ぶとダイアログが開き、二通りの記録方法があります。

- **フォームに入力** — 着想のタイトルと任意の説明を入力します。**これをテーマにする** オプションを選ぶと、単一の成果物ではなく、関連する着想をまとめるテーマ（そこから派生させた子の着想を通じて実現されます）になります。
- **エージェントに説明** — チャットのコンポーザーで着想を話し、オンラインのエージェントと一緒に形にします。オンラインのエージェントが必要なため、接続されていないときは使えません。説明しながら、大きなリクエストを子の着想に分割するようエージェントに頼むこともできます。

:::note[エージェントは何をするのか]
手動で作成した着想も、ほかの着想と同じパイプラインに入ります。エージェントに割り当てると、エージェントが要件詳細化を進め、審査用の提案を起草します。全体の流れは[着想を記録](/ja/guides/capture-an-idea/)をご覧ください。
:::

## 着想を編集・移動する、親を付け替える

着想を開くと詳細パネルが表示されます。そこから **着想を編集**（タイトルと説明）で編集、**着想を削除** で削除、**プロジェクトへ移動...** で別のプロジェクトへの移動ができます。移動ダイアログでは、確定する前に、着想と一緒に移動するものをプレビューできます。

パネルは **系統**、つまり着想が親子としてどう関係するかも管理します。

- **親を設定** / **親を変更** — この着想を別の着想の下に付けるか、別の親へ移します。
- **新しい着想を派生** — この着想から子の着想（独自の要件詳細化・提案・課題を持つ完全な着想）を作ります。
- **切り離す（トップレベルにする）** — 親のリンクを外し、着想をトップレベルに戻します。

**これをテーマにする** は、着想を単一の成果物にするか、関連する着想をまとめるテーマにするかを切り替えます。テーマは子をまとめるだけで、それ自体は提案になれません。[テーマの着想と派生した子の着想](/ja/guides/capture-an-idea/#テーマの着想と派生した子の着想)をご覧ください。

## 課題を手動で作成する（Quick Task）

ほとんどの課題は提案を承認したときに生成されますが、着想から提案までの一連のサイクルが要らない作業は、課題として直接追加できます。これが **Quick Task** です。**課題** ボードで **新しい課題** を選び、タイトルと説明、**優先度**、工数の見積もり、**受け入れ基準**（審査者が検証の基準にするチェックリスト）、そして任意の **依存関係**（**依存関係を追加** で、他の課題が先に完了することを条件にします）を入力します。手動で作成した課題は未着手・未割り当ての状態から始まり、提案から作成された課題と同じように担当や割り当てができます。

:::note[エージェントは何をするのか]
Quick Task も作成後は通常の課題です。エージェントに割り当てると、依存関係が満たされた時点でエージェントが担当して作業し、検証のために提出します。担当・割り当て・ステータスの流れは[課題を実行](/ja/guides/run-tasks/)をご覧ください。
:::

## 課題とその依存を編集する

課題を開くと同じパネルが表示され、今度は **課題を編集** というタイトルになります。任意のフィールドを変えて **変更を保存** するか、**課題を削除** で削除します。パネルの **作業を開始**、**レビューに提出**、**検証済みにする**、**割り当て** でステータスも進められます。

依存関係は二方向で表示されます。**依存先** にはこの課題が待っている上流の課題が、**これにブロックされている課題** にはこの課題を待っている下流の課題が並びます。課題は、依存先がすべて完了してはじめて開始できます。ボード上で、まだブロックされているカードを動かすと警告が表示されます。順序が安全だと分かっているときは、**強制的に移動** で上書きできます。

## 提案を手動で作成する

提案は通常 PM エージェントが書きますが、あなた自身で書くこともできます。**提案を作成** を選び、タイトルを入力し、その提案の元になる着想を選びます。選べるのはあなたが担当したか割り当てられた着想だけなので、一覧が空なら先に一つ担当してください。提案を作成すると編集画面が開くので、そこで計画を組み立てます。PRD・設計・仕様ごとに **文書を追加** を、作業単位ごとに（その受け入れ基準と依存を添えて）**課題を追加** を使います。計画が整ったら **レビューに提出** を選びます。エージェントが書いた提案と同じ承認の関門に送られます。

:::note[エージェントは何をするのか]
提案をエージェントが書いたか、あなたが書いたかにかかわらず、承認が判断の関門です。文書ドラフトと課題ドラフトを審査して承認すると、実際の文書と未着手の課題が作成されます。承認が何を作るかは[提案を審査](/ja/guides/review-a-proposal/)をご覧ください。
:::
