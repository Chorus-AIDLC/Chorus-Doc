**Agent Team**（エージェントチーム）は、あるプロジェクトで *あなた自身の* どのエージェントがどの種類の作業を担当するかを
Chorus に伝える仕組みです。設定する場所は二つあります。

- **チームテンプレート**：**設定 → エージェントチーム** にあり、あなたのエージェントを役割ごとにまとめた再利用できる組み合わせです。
- **プロジェクトのチーム**：**プロジェクト設定 → チーム** にあり、一つのプロジェクトで使うテンプレートと、そこで役割ごとに加えた変更です。

チームはあなたとあなたのエージェントにしか見えません。権限は一切付与せず、保存しても作業は割り当てられません。
あなたが着想を自分のエージェントに任せたときに初めて、*誰が何をするか* をチームが決めます。エージェント自体の作成は
[エージェントと API キーを管理する](/ja/guides/manage-agents/)をご覧ください。

## 四つの役割

どのチームにも同じ四つの役割があります。役割ごとにメンバーに必要なエージェント権限が決まっており、
それを持たないエージェントはその役割に追加できません。

| 役割 | メンバーの仕事 | 必要なエージェント権限 |
| --- | --- | --- |
| **プロダクト** | 着想を詳細化し、提案と文書を書きます。要件詳細化の確定は、その着想を統括するエージェントが行います。 | すべてのリソースの読み取り、および着想・提案・文書の書き込み |
| **開発** | 課題を実行し、検証に提出します。 | すべてのリソースの読み取り、および課題の書き込み |
| **レビュー** | 独立したレビューの判定を投稿します。 | すべてのリソースの読み取り |
| **リード** | 着想の割り当てと確定、課題の委任、提案と課題の関門、完了レポートの作成を担います。着想を引き継ぐ相手はリードです。 | すべてのリソースの読み取り、着想・提案・課題・文書の書き込み、および着想・提案・課題の管理 |

- **一つのエージェントが複数の役割を持てます。** 十分な権限を持つ一つのエージェントが、プロダクト、レビュー、リードを兼ねてもかまいません。
- **どの役割も省略できます。** メンバーのいない役割の作業は、通常どおり手動の流れで進みます。ただしレビューは例外で、レビューのメンバーがいなければ統括者が自分のレビュー担当サブエージェントを実行します。四つの役割がすべて空のチームも有効です。
- **プロジェクトでは、メンバーにプロジェクトへのアクセスも必要です。** エージェントは所有者のアクセス権で動くため、
  あなたのエージェントがそのプロジェクトで適格になるには、あなたがそのプロジェクトの **編集者** 以上である必要があります
  （[プロジェクトを閲覧できる人を管理する](/ja/guides/project-access/)を参照）。判定はコメントとして投稿されるため、レビューのメンバーにも必要です。

テンプレートエディターでは、役割名の横にある情報アイコンにフォーカスするかタップすると、その役割の正確な要件を確認できます。

## チームテンプレートを作成・編集する

1. **設定** を開き、**エージェントチーム** カードで **エージェントチームを管理** を選びます。
2. **チームを作成** を選びます。
3. **チーム名** を入力し、必要なら **説明（任意）** も入力します。
4. **役割の割り当て** で役割の行の **+** を選び、あなたのエージェントを一つ選びます。役割の権限が足りないエージェントは
   一覧に表示されますが選べず、どの権限が足りないかが示されます。メンバーを外すには、そのチップの **×** を選びます。
5. **チームを保存** を選びます。

選べるのはあなた自身のエージェントだけです。まだエージェントがなくても、空のチームを保存して、あとからメンバーを追加できます。

各テンプレートは、役割ごとにメンバーを並べたカードとして表示されます。変更するには **チームを編集** を選びます。
プロジェクトでテンプレートから役割を継承しているチームには、編集内容が自動的に反映されます。あとでメンバーが必要な権限を失った場合、
そのメンバーは警告付きでテンプレートに残ります。残すことも外すこともできますが、外すと適格になるまで再び追加できません。

### テンプレートを削除する

テンプレートカードの **…** メニューを開き、**チームを削除**、続いて **削除を確定** を選びます。削除は元に戻せませんが、
頼りにしているものは壊れません。そのテンプレートを使っていたプロジェクトのチームはすべて、現在のメンバー（役割ごとの変更を含む）を
**固定スナップショット** として保持し、以後どのテンプレートにも追従しません。エージェント、着想の割り当て、課題は変わりません。

## プロジェクトのチームを設定する

プロジェクトを開き、概要の右上で **設定** を選び、**プロジェクト設定** ダイアログで **チーム** タブを選びます。

チームタブは個人用です。プロジェクトにアクセスできる人は誰でも開いて自分のチームを設定でき、ほかの人（プロジェクトの管理者を含む）は
あなたのチームを見ることも変えることもできません。非公開プロジェクトの **一般** タブと違い、プロジェクトの管理者ロールは不要です。

### テンプレートを選ぶ

**個人テンプレート** であなたのテンプレートを一つ選びます（**テンプレートを管理** で「設定 → エージェントチーム」へ移動できます）。
四つの役割の行がテンプレートの内容で埋まります。別のテンプレートを選び直すと、それまでの役割ごとの変更は置き換えられます。

各役割の行にはバッジが付きます。

| バッジ | 意味 |
| --- | --- |
| **継承** | 役割のメンバーはテンプレートから来ており、今後のテンプレートの編集にも追従します。 |
| **上書き** | このプロジェクトでこの役割を変更しました。テンプレートの編集はもう影響しません。 |
| **固定スナップショット** | テンプレートが削除され、削除時に保持したスナップショットがメンバーになっています。ここで編集するか、新しいテンプレートを選びます。 |

### 役割ごとにメンバーを変更する

- 役割の行の **+** で追加し、メンバーのチップの **×** で外します。役割を少しでも変更すると、このプロジェクトではその役割全体が上書きされます。
- 役割の **…** メニューには、さらに二つの操作があります。
  - **役割を空にする**：テンプレートにメンバーがいても、このプロジェクトではその役割を意図的に空にします。その作業は手動の流れになります。ただしレビューの役割を空にした場合は、統括者が自分のレビュー担当サブエージェントを実行します。
  - **継承に戻す**：上書きをやめ、テンプレートのメンバーに戻します。チームが固定スナップショットの間は使えません。

### メンバーの状態を見る

各メンバーのチップには接続状態を示す点があります。チップにホバー、フォーカス、またはタップすると、たとえば
「オンライン · 実行中 / 待機中 2」のように表示されます。オフラインのエージェントも役割には残りますが、
Chorus が推薦するのはオンラインのメンバーだけで、その中では手の空いているメンバーが優先されます。プロダクトまたは開発の適格なメンバーが全員オフラインの場合、
統括者自身がオンラインでその役割に適格なら Chorus は統括者自身を推薦し、そうでなければその手順は手動に戻ります。

警告アイコンの付いたチップは、このプロジェクトで **適格ではありません**。ヒントに理由が表示されます。必要な権限が足りないか、
あなたがプロジェクトの **編集者** 権限を持っていないかのどちらかです。適格でないメンバーも表示されたままなので、どうするかはあなたが決めます。
Chorus がそれらを勝手に外したり差し替えたりすることはありません。追加したばかりのメンバーの適格性と接続状況は、保存後に更新されます。

### 保存、破棄、連携解除

- **チームを保存** で保存します。保存しても作業は一切割り当てられません。
- チームの変更を保存しないままタブを切り替えたりダイアログを閉じたりすると、「チームの変更を破棄しますか？」と確認されます。
  戻るには **編集を続ける**、変更を捨てるには **変更を破棄** を選びます。
- **連携解除**、続いて **解除を確認** を選ぶと、プロジェクトのチームを削除します。削除されるのはあなたの個人設定だけで、
  既存の着想の割り当てとすべての課題はそのまま残り、テンプレートも削除されません。

## 着想をリードに引き継ぐ

チームを連携しても作業は動きません。このプロジェクトで未完了のあなたの着想を一度に一人のリードへ任せるには、
チームタブ下部の **引き継ぐ…** を使います。

1. 先にチームを保存します。保存していない変更があると **引き継ぐ…** は使えません。
2. **引き継ぐ…** を選びます。「Ideaの明示的な引き継ぎ」ダイアログで、**リード** の役割からエージェントを一つ選びます。
   オフラインのリードでもかまいません。適格でなくなったリードは表示されますが選べません。
3. **引き継ぎをプレビュー** を選びます。プレビューには移動するすべての着想が一覧され、件数とプレビューの有効期限（数分後）が表示されます。
   対象は、このプロジェクトで現在あなたまたはあなたのエージェントに割り当てられている未完了の着想だけです。
   未割り当ての着想やほかの人の着想は決して含まれません。
4. **Ideaの引き継ぎを確認** を選びます。

引き継ぎで変わるのは着想の割り当て先だけです。課題、課題の割り当て、セッション、進行中の作業は保たれます。
プレビュー後に何かが変わった場合や、プレビューの期限が切れた場合、Chorus は何も再割り当てせず、新しいプレビューを求めます。
**プレビューを更新** を選んでから、もう一度確定してください。

引き継ぎにはプロジェクトの **編集者** 権限が必要です。閲覧者権限でもメンバーの削除、役割を空にすること、テンプレートの連携解除はできますが、メンバーは追加できません。メンバーが追加される変更（メンバーを含むテンプレートの適用を含む）は保存に失敗します。**引き継ぐ…** も使えません。

最後に引き継いだリードが、あとでリードの役割から外されたり、適格でなくなったり、削除されたりすると、チームタブにそのエージェント名を挙げた警告が表示されます。
ほかに適格なリードがいても、Chorus が自動で再割り当てすることはありません。直すには、あなたが選んだリードへ改めて引き継ぎを行います。

## チーム管理の着想の進み方

チームをプロジェクトに連携したあとで、*あなた* が着想を自分のエージェントに割り当てると（直接割り当てても **引き継ぐ…** を使っても）、
その着想は **チーム管理の着想**（Team-managed Idea）になります。チーム管理の着想の下で、あなたのエージェントが割り当てた派生の着想もチーム管理になります。

次の着想は通常の流れのままです。チームを連携する前に割り当てられたもの、ほかの人が割り当てたもの、エージェントが自分で担当したもの。
チームの連携を解除すると、すべての着想が通常の流れに戻ります。

チーム管理の着想を割り当てられたエージェントが、その着想を **統括** します。リードの役割に入っている必要はありません。
統括するエージェントは、各ステップをあなたのチームに振り分けます。

- **プロダクト。** 統括者は、要件詳細化と提案の作成をプロダクトのメンバーに委任できます。委任されたメンバーは要件詳細化を始め、
  その着想の提案を作成・提出できますが、要件詳細化の確定、承認、検証、着想の再割り当てはできません。着想を再割り当てすると委任は終わります。
- **開発。** 統括者は課題を、適格でオンラインの開発メンバーに割り当てます。その中では手の空いているメンバーが優先されます。誰もオンラインでない場合は[メンバーの状態を見る](#メンバーの状態を見る)をご覧ください。
  差し戻された課題は、できるかぎり元の担当者に戻ります。候補が並んだときは統括者が決めます。
- **レビュー。** 下の[レビューの振り分け方](#レビューの振り分け方)をご覧ください。

レビュー以外の役割が空であるか適格なメンバーがいない場合、そのステップは通常の手動の流れに戻ります。レビューの役割が空の場合の扱いは異なり、後述のとおりです。統括者自身が必要な権限やプロジェクトへのアクセスを失うと、
問題を直すか着想を再割り当てするまで、その着想のチームによる振り分けは一時停止します。

## レビューの振り分け方

チーム管理の着想では、レビューはその場で選んだレビュー担当ではなく、あなたの **レビュー** 役割に回ります。
提案が提出されたとき、または課題が検証に提出されたとき、統括者に通知が届き、統括者がレビューを振り分けます。

- 適格でオンラインのレビューメンバーが優先されます。再提出されたものは以前にレビューしたレビュー担当に戻り、次に手の空いているメンバーが選ばれます。
  誰も除外されないため、その作業を行ったエージェントがレビュー担当に選ばれることもあります。
- レビューの役割が空の場合や、適格なメンバーが誰もオンラインでない場合、統括者は代わりに自分の独立したレビュー担当サブエージェントを実行します。
  そのためレビューが止まることはありません。
- その着想のすべての提案にわたって、どの課題も検証に提出済み、完了、またはクローズになると、統括者は着想全体の変更に対するレビューも開始します。これは課題のレビューと並行して進み、
  これが通ってはじめて完了レポートが書かれます。

### レビュー依頼

レビューを別のエージェントに任せるとき、統括者は提案、課題、または着想に **レビュー依頼** のコメントを投稿します。依頼にはラウンドが書かれ、
レビュー担当を一人だけメンションし、結果を誰が受け取るかが示されます。合格なら統括者へ、課題が不合格ならその課題の開発者へ、
提案が不合格ならプロダクトの委任先へ（いなければ統括者へ）届きます。起こされるのは名指しされたレビュー担当だけで、
レビューを始められるのはレビュー依頼だけです。通常のコメントは、何が書かれていてもレビューを始めません。レビュー担当はオンラインである必要があり、
オフラインなら依頼は失敗し、あとで再試行できます。

レビュー担当は読むだけで、すべての指摘を並べた `VERDICT:` コメントを一つ投稿します。自分で却下、差し戻し、検証、課題の作成を行うことはありません。
判定がメンションするのは次に動くべき相手だけで、「受け取りました」だけの返信は誰もしません。再提出された提案や課題は同じレビュー担当が再レビューし、
最大三ラウンドを超えると判断は人に委ねられます。判定と指摘 ID の仕組みは[自動化の挙動](/ja/guides/plugin-automation/#レビュー担当サブエージェント)をご覧ください。

### 承認は通常の流れのまま

チームは、誰が承認や検証をできるかを変えません。統括者が課題を検証するのは、今回のラウンドの判定が合格したあとで、しかも検証の権限を持っている場合だけです。
提案には引き続き人の承認が必要で、判定はその人への助言です。ただし着想を **Yolo** で開始した場合は、レビューが合格したあと統括者が提案を承認できます。
[提案を審査](/ja/guides/review-a-proposal/)と[検証して完了](/ja/guides/verify-and-complete/)をご覧ください。

## タスクとレビューの会話

Chorus daemon がエージェントを起こすと、課題の作業とレビューはそれぞれ専用の会話で進み、エージェントの **会話** 一覧で着想の会話の下にまとめられます。

- 「タスク: 課題名」という会話：課題が、その課題に割り当てられたエージェントを起こしたときに開きます。
  一つのエージェントが同じ着想の複数の課題を、同時実行数の上限まで並行して進められます。
- 「レビュー: 対象名」という会話：エージェントが提案、課題、または着想のレビューを依頼されたときに開きます。
  レビューがレビュー担当の開発用の会話を引き継ぐことはないため、その作業を行ったときの記憶なしで始まります。
  同じレビュー担当が同じ対象を再レビューするときは、以前のレビューの会話を引き継ぎます。

それぞれの子会話には独自の記録、実行状態、**中断** と **再開** の操作があり、着想の会話と同じ作業ディレクトリで始まります。
子会話には返信欄がないため、指示は着想の会話から送ります。[リモートのエージェントで作業を始める](/ja/guides/remote-control/)と
[セッションを中断して再開する](/ja/guides/session-recovery/)をご覧ください。OpenClaw や Hermes など一部のランタイムでは、引き続き着想ごとに会話は一つです。

## チームがしないこと

- **何も付与しません。** チームの役割がエージェントの権限やプロジェクトへのアクセスを増やすことはありません。どの操作も、エージェントの権限とあなたのプロジェクトでのロールで確認されます。
- **自分から作業を割り当てません。** 保存、上書き、テンプレートの変更や削除、連携解除によって、着想や課題が割り当てられたり、再割り当てされたり、割り当てが取り消されたりすることはありません。
  それを行うのは、明示的な割り当てか確定した引き継ぎだけです。
- **承認の流れを変えません。** 提案の承認と課題の検証は、上で説明したとおり通常の流れに従います。
- **共有されません。** ほかのプロジェクトメンバー（管理者を含む）はあなたのチームを見られず、テンプレートはエージェントがオンラインかどうかも示しません。

## エージェント向け

- `chorus_checkin` には `projectTeams` マップが含まれ、あなたが作業している各プロジェクトについて所有者のチームが入ります。
  `chorus_get_project_team` は、アクセスできる任意のプロジェクトのチームを読み取ります。
- `chorus_get_idea_team_context` は、着想がチーム管理かどうか、有効か一時停止中か、誰が統括しているかを返します。
  チーム管理の着想で動く前に、起こされるたびに読み直してください。
- 統括者は `chorus_recommend_team_agent` でプロダクト、開発、レビューのメンバーを選び、`chorus_delegate_team_product` でプロダクトの作業を委任し、
  `chorus_request_review` でレビュー依頼を送ります。推薦は割り当ても起動もしません。
- エージェントはチームの設定を変更できず、引き継ぎを確定することもできません。これらは Web UI でのみ行います。

入力と出力は [MCP ツールカタログ](/ja/reference/mcp-tools/#エージェントチームのツール)をご覧ください。
