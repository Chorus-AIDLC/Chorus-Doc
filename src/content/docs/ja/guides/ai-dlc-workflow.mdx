Chorus は **AI-DLC（AI 駆動開発ライフサイクル）** の上で動きます。これは、あらゆる仕事を粗い着想から検証済みの結果まで運ぶ、固定されたパイプラインです。あなたと AI エージェントは同じパイプラインを共有しますが、演じる役割は違います。本ページはその役割と、仕事が通り抜ける各段階を説明し、それから各段階の手順ガイドへ案内します。

## 反転した対話

ほとんどの AI ツールは一方向です。人がプロンプトを書き、AI がそれを実行します。Chorus はその向きを逆にします。

**AI が提案し、あなたが検証します。** エージェントはあなたの着想を質問に変え、次に具体的な提案、つまり設計と仕様の文書に一連の課題を加えたものに変えます。あなたがその提案を読んで承認するまで、何も作られません。そして結果を受け入れ基準に照らして確認するまで、何も完了しません。あなたはどの関門でも判断する側にとどまり、その間の起草と実行はエージェントが担います。

これが「反転した対話」です。*人がプロンプト → AI が実行* ではなく、*AI が提案 → 人が検証*。下に並ぶ各段階は、あなたが判断を下す関門です。

## パイプライン

仕事は一本の道に沿って流れます。

**着想 → 提案 → 文書 + 課題 → 実行 → 検証 → 完了。**

ワークスペースは一度だけ整えれば、あとはどのリクエストもこの道をたどります。下の表は、あなたの側から見た各段階を示し、その手順ガイドへリンクします。

<div class="table-scroll" role="region" aria-label="AI-DLC パイプラインの段階" tabindex="0">

  | 段階 | あなたがすること | ガイド |
  | --- | --- | --- |
  | プロジェクトを整える | プロジェクトを作成し、作業ディレクトリを割り当てて開きます。以下のすべてはプロジェクトの中に存在します。 | [プロジェクトを作成](/ja/guides/create-a-project/) |
  | 着想 | やりたいことを着想として記録します。エージェントは要件詳細化のラウンド、つまり短い一問一答を、双方の理解が一致するまで繰り返します。そのうえであなたが確認して確定します。 | [着想を記録](/ja/guides/capture-an-idea/) |
  | 提案 | エージェントが提案を起草して提出します。あなたはその文書と課題の下書きを読み、承認するか却下します。承認すると、下書きから **文書** と **課題** が生成されます。 | [提案を審査](/ja/guides/review-a-proposal/) |
  | 実行 | 課題は担当されるか割り当てられ、一つずつ進められます。あなたは各課題がステータスと依存グラフをたどって検証へ向かう様子を追います。 | [課題を実行](/ja/guides/run-tasks/) |
  | 検証 → 完了 | あなたは各課題を受け入れ基準に照らして検証します。仕事が検証されると着想は完了し、そのレポートを読めます。 | [検証して完了](/ja/guides/verify-and-complete/) |

</div>

この順にガイドを読み進めれば、パイプラインを離れることなく、空のワークスペースから検証済みで完了した着想までたどり着けます。

:::note[エージェントは何をするのか]
エージェントはどの段階でもあなたの対役です。要件詳細化の質問を投げ、提案を起草し、承認済みの課題を実行し、あなたの審査のために根拠を整えます。Chorus は各アクションの効果、つまり新しい要件詳細化のラウンド、提出された提案、`to_verify` に達した課題を見せ、あなたの判断を待ちます。エージェントがどう接続し、何ができるのかは、[エージェントプラットフォーム参考](/ja/reference/agents/)をご覧ください。
:::
