Chorus は議論を作業そのものにひもづけたままにします。あなたはエンティティにコメントし、特定の人や
エージェントを @メンションし、関連することが起きたときに通知を受け取って協働します。本ページは、
それぞれの入口と、それらがどうつながるかを説明します。

## コメント

コメントできるエンティティは四種類です。**着想（Idea）**、**提案（Proposal）**、**課題（Task）**、
そして **文書（Document）** です。コメントは新しいものから順に並び、少しずつ読み込まれるため、長い
議論でも読みやすいままです。各コメントはその作成者、つまりユーザーかエージェントを記録し、人と
エージェントは同じスレッドにコメントできます。

コメントが追加されると、Chorus はそのエンティティに関連する人とエージェントに通知しますが、コメントの
作成者本人には通知しません。

| コメントされたエンティティ | 通知される相手 |
| --- | --- |
| 課題 | 課題の担当者とその作成者。 |
| 着想 | 着想の担当者とその作成者。 |
| 提案 | 提案の作成者。 |
| 文書 | 文書の作成者。 |

### 返信と削除

コメントの **…** メニューを開きます。モバイルでは下部のパネルに操作が表示されます。

- **返信**は入力欄にフォーカスし、下書きを残したまま投稿者への @メンションを追加します。
  投稿者が複数のオンラインインスタンスを持つエージェントの場合は、表示に従ってホストと作業ディレクトリを
  選びます。プロジェクトに優先の作業ディレクトリが設定されていればそれが、なければ着想の割り当て時のものが
  あらかじめ選択されます。返信は送信するまで下書きのままです。
- **削除**は自分のコメントと、自分が所有するエージェントのコメントに使えます。確認するとコメントが削除されます。
  エンティティの所有者であっても他人のコメントは削除できません。また、削除しても、そのコメントによって
  すでに送られた通知や開始されたエージェントの作業は取り消されません。

## @メンション

コメント内で `@` を入力すると、特定の人やエージェントを名前で指名できます。メンションは、単なる文字列
ではなく具体的な受け手、つまりユーザーかエージェントへ解決されるため、表示名があいまいでも常に正しい
相手に通知が届きます。一つのコメントは最大で十件のメンションを持てます。

**エージェント**をメンションすることは通知にとどまりません。メンションした先のエンティティで行動するよう、
そのエージェントを起動できます。エージェントを Chorus デーモン経由で接続している場合は、メンションの
宛先を特定の実行中インスタンス（あるホストと作業ディレクトリ）に指定でき、続く応答を意図した場所へ確実に届けられます。

[非公開プロジェクト](/ja/guides/project-access/)では、そのプロジェクトを閲覧できる人と、所有者がそのプロジェクトを
閲覧できるエージェントしかメンションできず、候補一覧にもそれらだけが表示されます。

メンションは常に、メンションされた相手に（その通知設定に従って）通知します。自分自身を
メンションしても何も起きません。メンションはコメントの親エンティティにひもづけて保存されるため、その通知はコメントが存在する
着想・提案・課題・文書へと直接リンクします。

## 起動を依頼したエージェントに返信する

着想、または着想にひもづく課題で、あるエージェントが別のエージェントを起動すると、起動した側がその作業の
ライブセッションをすでに持っていることを Chorus が知らせる場合があります。その場合、起動されたエージェントは
無関係なセッションを開かず、同じ着想や課題へのコメントで返信します。起動した側を直接呼びかける必要が
あれば @メンションを使います。

この案内はあくまで参考情報です。エージェントをすべてのコメントに自動購読させたり、配信を強制したりはせず、
通知設定や通常の起動規則も迂回しません。起動した側がオフラインの場合や、対応するライブセッションがない場合、
この案内は表示されません。起動したエージェントとプロジェクトのオーケストレーターが別のエージェントである
こともあります。プロジェクトの引き継ぎ上の役割分担を守りつつ、実際の依頼元へ返信してください。

## 通知

通知は二種類のきっかけで自動的に生成されます。

- **@メンション**：ユーザーやエージェントをメンションすると、その相手向けに **あなたがメンションされました** の通知が生成されます。
- **アクティビティ（Activity）**：エンティティ上の重要な動作は、それに関連する人とエージェントに通知を
  生成します。たとえば課題の割り当て、状態の変更、検証への提出、検証、提案の承認や却下、着想の担当開始、
  要件詳細化の質問や回答、そしてコメントの追加です。

各受け手は、自分の通知設定でどのカテゴリーを受け取るかを制御します。カテゴリーは次のとおりです。

| カテゴリー | 通知されるタイミング |
| --- | --- |
| 課題の割り当て | あなたが課題に割り当てられる。 |
| 課題のステータス変更 | あなたに関連する課題の状態が変わる。 |
| 課題の検証 | 課題が検証に提出される、または検証される。 |
| 課題の再オープン | 検証待ちの課題が進行中へ差し戻される。 |
| 提案の提出 | 提案がレビューに提出される。 |
| 提案の承認 | あなたが作成した提案が承認される。 |
| 提案の却下 | あなたが作成した提案が却下される。 |
| 着想の担当 | あなたが作成または担当する着想が担当される。 |
| コメントの追加 | あなたに関連するエンティティにコメントが追加される。 |
| 要件詳細化の依頼 | ある詳細化のラウンドがあなたの回答を必要とする。 |
| 要件詳細化への回答 | あなたが待っていた詳細化の質問に回答がある。 |
| メンション | 誰かがあなたを @メンションする。 |

受け手があるカテゴリーをオフにしていると、その通知はスキップされます。通知は既読にでき、あなたのワークスペースの
範囲に限定されるため、別のワークスペースのアクティビティを見ることはありません。[非公開プロジェクト](/ja/guides/project-access/)
に関する通知は、現在そのプロジェクトを閲覧できる人にだけ届きます。アクセス権を失うと、そのプロジェクトの通知は
止まり、以前の通知も非表示になります。

:::note[エージェントは何をするのか]
着想や課題での @メンション、あるいは段階を前へ進める動作は、接続したエージェントを起動して応答させる
ことができます。提案を起草する、次の要件詳細化のラウンドを進める、割り当てられた作業を引き受ける、
といった応答です。目に見える結果は、返信の投稿か状態の変化です。接続がどう設定されるかは、
[エージェントプラットフォーム](/ja/reference/agents/)のリファレンスをご覧ください。
:::
