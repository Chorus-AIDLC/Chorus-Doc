# Claude Code

Claude Code には第一者の Chorus プラグインがあります。対話的な Claude Code セッションで Chorus
ツールとワークフロースキルをサポートし、サポートされる Chorus デーモンのバックエンドとしても
動作します。

インストール前に、[エージェントのアクセスを準備する](/ja/guides/administrator-setup/)に従って
エージェントキーを作成します。

## プラグインをインストールする

最も手早い方法は `chorus` CLI です。プラグインをインストールし、認証情報を保存してくれます。

```bash
npm install --global @chorus-aidlc/chorus
chorus agents add --agents claude
```

プロンプトが出たら、Chorus URL とエージェントキーを入力します。`chorus agents add` は
`claude plugin marketplace add` / `claude plugin install` を代わりに実行し、`CHORUS_URL`、
`CHORUS_API_KEY`、`CHORUS_AGENT_PROFILE` をユーザー全体の `~/.claude/settings.json` の `env`
ブロックに書き込むため、対話的な Claude Code セッションは手動の環境設定なしで認証されます。
その後、Claude Code を再起動します。

手動でインストールする場合は、起動するシェルで認証情報を設定します。

```bash
export CHORUS_URL="https://chorus.example.com"
export CHORUS_API_KEY="cho_REDACTED"
```

次に、Claude Code 内からプラグインを追加します。

```text
/plugin marketplace add Chorus-AIDLC/chorus
/plugin install chorus@chorus-plugins
```

インストール後に Claude Code を再起動します。

## リモート起動を有効にする

対話的な Claude Code セッションからのみ Chorus を使う場合は、このセクションを飛ばしてください。
それ以外の場合は、[ランタイムを接続する](/ja/guides/operator-onboarding/)に従い、バックエンドとして
`claude-code` を選びます。[デーモンの運用](/ja/guides/daemon-operations/)でオンラインを維持する前に、
フォアグラウンドで接続を確認してください。

## 0.20.0 のデーモン動作

起動ごとに一つの `claude -p` プロセスを作り、ターン終了後に終了する点は従来どおりです。Chorus は双方向の **stream-json** 入出力を使い、制御応答のために接続を開いたままにします。既存セッションと `claude --resume` は引き続き利用できます。プレーンテキストへのフォールバックや通信方式の切り替えはありません。Linux 上の Claude Code **2.1.283 と 2.1.284** で実行検証済みです。これは検証済みバージョンであり、すべての Claude リリースに対する最低互換バージョンの保証ではありません。

- **中断**：最初にプロトコルで中断します。`sigintTimeoutMs` 以内に停止しなければプロセスツリーを強制終了します。既定値は従来どおり 10 秒です。Windows の終了処理はプラットフォームテストで検証しており、実機検証ではありません。
- **制限対象ツール**：`--chorus-only` では Chorus 以外のツールを明示的に拒否し、Chorus ツールの使用かコメントでの質問を案内します。ログには拒否したツール名だけを記録し、入力内容は記録しません。YOLO の動作は変わりません。
- **質問**：デーモン起動では YOLO を含め `AskUserQuestion` を無効にします。端末で回答する人がいないため、Chorus のコメントか要件の明確化を使います。対話的な Claude Code セッションの質問フローは変わりません。

更新後は実際に導入されている Claude Code で、チェックイン、追加ターン、中断と再開を確認してください。プロトコルエラーは[デーモンのログ](/ja/guides/daemon-operations/)、続行手順は[セッションの復旧](/ja/guides/session-recovery/)を参照してください。

## 接続を確認する

Claude Code で `/plugin list` を実行し、`chorus@chorus-plugins` が有効になっていることを確認します。
次に、Claude Code に `check in to chorus` を依頼します。成功すると、応答が接続されたエージェントと
その権限を示します。

デーモンモードでは、Chorus の**設定 → エージェント**を開き、想定したホストと作業ディレクトリが
オンラインであることを確認します。

## 機能と制限

- プラグインは Chorus MCP ツール、ワークフロースキル、そしてライフサイクル統合を提供します。
- デーモンモードは、リモート起動、追加指示、中断、再開をサポートします。
- リモート作業は、登録された作業ディレクトリ内で、ローカルの OS ユーザーが利用できるすべてに
  アクセスできます。信頼できるディレクトリのみを登録してください。

共通の運用手順については、[リモート制御](/ja/guides/remote-control/)と
[セッションの復旧](/ja/guides/session-recovery/)を使ってください。

## ターミナルから再開する

自分のターミナルから進行中の会話を引き継ぐには、チャット UI からそのセッション ID をコピーし
（トランスクリプトのヘッダーにある**Copy session ID**）、その会話の作業ディレクトリで実行します。

```bash
claude --resume <sessionId>
```

コピーした ID は、Chorus がセッションを再開するときに Claude Code へ渡すのと同じ ID です。
Claude Code バックエンドの場合、それは直接の着想の UUID です。完全な流れは
[セッションの中断と再開](/ja/guides/session-recovery/#ターミナルから引き継ぐ)を参照してください。

## よくある問題

- **プラグインが表示されない：** Claude Code を再起動し、`/plugin list` を確認します。
- **チェックインが認可されない：** エージェントキーを作成またはローテーションし、次に
  `chorus agents add` を再実行して（または `~/.claude/settings.json` の `env` ブロックを更新して）、
  Claude Code を再起動します。
- **デーモンがオフライン：** `chorus daemon status` を実行し、次に
  [トラブルシューティング](/ja/guides/troubleshooting/)を参照します。
- **想定と異なるプロジェクトが表示される：** 意図した絶対パスの `--cwd` 値でデーモンを
  再インストールします。

## サブエージェントのセッション

プラグインが管理するサブエージェントのセッション名には Agent の種類を使います。
同じ種類の並列サブエージェントは Chorus セッションを共有でき、最後の一つが終了するまで開いたままです。
一つの終了で、まだ動いている別のサブエージェントの追跡が終了することを防ぎます。
