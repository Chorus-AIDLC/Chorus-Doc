すでに使っているエージェントを選び、そのうえで、そのエージェントで Chorus から
リモートに作業を開始する必要があるかどうかを判断します。

| プラットフォーム | サポート提供元 | 適した用途 | リモート起動 | 常駐ランタイム |
| --- | --- | --- | --- | --- |
| [Claude Code](./claude-code/) | Chorus チーム | 完全な Chorus ワークフローを求める Claude Code ユーザー | 対応（Chorus デーモン経由） | Chorus デーモン |
| [Codex](./codex/) | Chorus チーム | 完全な Chorus ワークフローを求める Codex ユーザー | 対応（Chorus デーモン経由） | Chorus デーモン |
| [Kiro](./kiro/) | Chorus チーム | 完全な Chorus ワークフローを求める Kiro CLI ユーザー | 対応（Chorus デーモン経由） | Chorus デーモン |
| [OpenClaw](./openclaw/) | Chorus チーム | すでにゲートウェイを運用している OpenClaw ユーザー | 対応（OpenClaw 経由） | OpenClaw ゲートウェイ |
| [DeepSeek Harness](./dsh/) | Chorus チーム | 完全な Chorus ワークフローを求める DeepSeek Harness ユーザー | 対応（Chorus デーモン経由） | Chorus デーモン |
| [OpenCode](./opencode/) | コミュニティ | コミュニティサポートで問題ない OpenCode ユーザー | 非対応 | 非対応 |
| [Pi](./pi/) | Chorus チーム | 完全な Chorus ワークフローを求める Pi ユーザー | 対応（Chorus デーモン経由） | Chorus デーモン |
| [汎用 MCP クライアント](./generic-mcp/) | MCP 互換のみ | 別の MCP クライアントから Chorus ツールを呼び出す | 非対応 | 非対応 |

Claude Code、Codex、Kiro、Pi、DeepSeek Harness が、サポートされる Chorus デーモンのバックエンドです。
OpenClaw は自前のゲートウェイとプラグインを通じてオンラインを維持します。OpenCode および汎用 MCP
クライアントは対話的に接続し、Chorus デーモンのバックエンドとしては選択できません。

API キーと権限については、まず[エージェントのアクセスを準備する](/ja/guides/administrator-setup/)を
ご覧ください。Claude Code、Codex、Kiro、Pi、DeepSeek Harness をリモートで利用可能にするには、プラットフォームの
セットアップを終えたあとで[Chorus デーモンを運用する](/ja/guides/daemon-operations/)に進みます。

## プラグインが同梱するもの

上記の各プラットフォームページでは、初回インストールと接続チェックを順に説明します。この
セクションでは、Chorus プラグインが各ランタイムに実際に同梱するもの、そしてそれを最新に保つ
方法を扱います。インストール手順は繰り返しません。

プラグインは、AI コーディングランタイムを Chorus の協働者に変えます。Chorus MCP ツール、各段階の
ワークフロースキル、レビュー用サブエージェント、そしてセッションのライフサイクル自動化を提供します。
ランタイムごとに個別に公開され、名前はいずれも `chorus` です。以下では Claude Code と Codex を
詳しく説明します。OpenClaw、Kiro、Pi は機能の範囲が狭いか形が異なるため、短い説明とリンクに
とどめます。

### Claude Code

Claude Code プラグイン（`chorus@chorus-plugins`）は次を同梱します。

- **Chorus MCP ツール**：`CHORUS_URL` と `CHORUS_API_KEY` から Chorus MCP サーバーを設定する
  `.mcp.json` テンプレート。`chorus agents add` がこれらを `~/.claude/settings.json` の `env`
  ブロックに書き込むため、対話的なセッションは手動のエクスポートなしで認証されます。
- **ワークフロースキル**：`/chorus` の総覧に加え、`/chorus:idea`、`/chorus:proposal`、
  `/chorus:develop`、`/chorus:review`、`/chorus:quick-dev`、`/chorus:yolo` として呼び出す各段階の
  スキル。
- **レビュー用サブエージェント**：3 つの読み取り専用レビュアー `chorus:proposal-reviewer`、
  `chorus:task-reviewer`、`chorus:code-reviewer`。それぞれが `VERDICT` コメントを投稿します。
- **セッションライフサイクルフック**：チェックイン、セッションの発見と作成、ハートビートの送信、
  そしてチェックアウトとセッションのクローズを自動で行うフック。加えて、提出後にメインエージェントへ
  レビュアーの起動を促す `PostToolUse` フック。
- **設定トグル**：各レビュアーの有効・無効化、レビュー回数の上限設定、OpenSpec モードのオン・オフを
  切り替えるプラグインの `userConfig` オプション。

### Codex

Codex プラグイン（Codex 版 `chorus@chorus-plugins`）は次を同梱します。

- **ワークフロースキル**：`$` プレフィックスで呼び出す 7 つのスキル `$chorus`、`$idea`、
  `$proposal`、`$develop`、`$review`、`$quick-dev`、`$yolo`。名前空間付きのため、完全修飾名は
  `chorus:<skill>` です。
- **レビュー用サブエージェント**：Claude Code と同じ 3 つの読み取り専用レビュアー
  `chorus-proposal-reviewer`、`chorus-task-reviewer`、`chorus-code-reviewer`。
- **セッション対応フック**：セッション開始時のチェックイン、ターンごとのリマインダー、そして提案の
  提出、課題の提出、または着想の提案の最後の課題が検証されたあとに促す `PostToolUse` レビュアー
  通知。Codex には、Claude Code の `TeammateIdle` および `TaskCompleted` フックに相当するものは
  ありません。

Codex の MCP サーバーはプラグインに同梱**されません**。Codex はプラグインの MCP 設定内で
`${VAR}` を展開しないため、`chorus agents add` はキーを設定に保存せずに Codex を設定します。
`CHORUS_URL` / `CHORUS_API_KEY` / `CHORUS_AGENT_PROFILE` を `~/.codex/.env`（Codex が起動時に
読み込む）に書き込み、`~/.codex/config.toml` に `bearer_token_env_var = "CHORUS_API_KEY"` を
設定するため、リテラルのキーがディスクに保存されることはありません。Codex にはプラグイン設定
（`userConfig`）もないため、レビューと OpenSpec の挙動は、プラグインのトグルではなくスキルによって
制御されます。

### その他の公式統合：OpenClaw、Kiro、Pi

これらのランタイムには公式の統合がありますが、その機能は Claude Code や Codex とは異なります。
以下の説明は、同等性の主張ではなく参照先として扱ってください。

- **OpenClaw**：Chorus MCP ツールとワークフロースキルを備えたプラグイン。Chorus デーモンではなく
  OpenClaw ゲートウェイを通じて利用可能な状態を保ち、同じワークフローライフサイクルフックは公開
  しません。[OpenClaw](/ja/reference/agents/openclaw/) を参照してください。
- **Kiro**：ツール、ワークフロースキル、レビューエージェント、フックを備えた統合。ワークスペース
  単位でもユーザー全体でもインストールできます。[Kiro](/ja/reference/agents/kiro/) を参照してください。
- **Pi**：公開された `@chorus-aidlc/chorus-pi` npm パッケージ（`pi install npm:@chorus-aidlc/chorus-pi`）で、
  Chorus MCP ツール（`pi-mcp-adapter` 経由）、ワークフロースキル、パッケージ相対のレビュアー
  エージェント、Pi 公式の `subagent` ツール、Pi ネイティブのイベントフックを備えます。Pi は
  **起動可能な Chorus デーモンバックエンド**（`chorus daemon --agent pi`）ですが、独自のネイティブ
  MCP や権限システムは持ちません。[Pi](/ja/reference/agents/pi/) を参照してください。

## プラグインをアップグレードする

アップグレードはその場で行え、API キーと Chorus URL は影響を受けません。設定済みの Claude Code、Codex、Kiro、Pi のプロファイルでは、`chorus upgrade --plugins` を使うと、エージェントの再登録や認証情報のローテーションをせずに CLI と Chorus プラグインを更新できます。[CLI の更新範囲と完了状態](/ja/reference/cli/#cli-とプラグインを更新する)を参照してください。以下のセットアップ手順は、エージェントの選択や認証情報の変更にも引き続き使えます。

- **どのエージェントでも**：`--update-installed` を付けてセットアップを実行し、更新するエージェントを
  選びます。このフラグがないと、完了している既存のインストールはスキップされる場合があります。

  ```bash
  chorus agents add --update-installed
  ```

- **Claude Code**：`/plugin` メニューからプラグインを管理するか、marketplace add と install を
  再実行して最新版を取得することもできます。

  ```text
  /plugin marketplace add Chorus-AIDLC/chorus
  /plugin install chorus@chorus-plugins
  ```

  Claude Code を再起動し、`/plugin list` を実行して新しいバージョンが有効になっていることを
  確認します。

- **Codex**：`chorus agents add --update-installed` を再実行すると、プラグインと `~/.codex/.env` の認証情報が更新
  されます。これは API キーをローテーションする方法でもあります。最後に Codex 内で
  `/plugins` を実行します。

OpenClaw、Kiro、Pi は、`chorus agents add --update-installed` を再実行するか、インストール時と同じ仕組みで
アップグレードします。手順は上記の各プラットフォームページに記載しています。

## プラグインをアンインストールする

- **Claude Code**：`/plugin` メニューを開き、`chorus@chorus-plugins` を無効化または削除します。
  プラグインを削除すると、そのフックとレビュー用サブエージェントも削除されます。環境内の
  API キーはプラグインの成果物ではありません。不要になった場合は別途削除してください。
- **Codex**：`/plugins` メニューからプラグインを無効化または削除します。MCP サーバーは別に
  設定されているため、完全に切断するには `~/.codex/config.toml` から `[mcp_servers.chorus]`
  セクションを、`~/.codex/.env` から Chorus のキーも削除します。一度限りのバックアップが
  `config.toml.chorus-bak` に保存されます。

OpenClaw、Kiro、Pi は、上記の各プラットフォームページで説明しているとおり、ランタイム自身の
プラグインまたはパッケージマネージャーから統合を削除します。

## バージョンの整合

プラグインと同梱スキルはまとめてバージョン管理され、**単一の Chorus アプリケーションバージョン**を
追随します。プラグインマニフェストの `version` フィールドは稼働中の Chorus リリースと一致し、
スキルの frontmatter の `version` もそれに合わせて変わるため、プラグインのリリースは対象とする
アプリケーションと揃います。Chorus をアップグレードするときは、プラグインも一致するバージョンに
アップグレードしてください。プラグインが報告するバージョンは、そのスキルのバージョンでもあります。

スキルは Claude Code と Codex のどちらでもプラグインに同梱され、プラグインとともに更新されます。
個別にインストールしたり同期を保ったりする必要はありません。

## エージェント向け

- **トリガー：** 読者（またはエージェント）がこのページに来るのは、プラットフォームを選ぶため、
  あるいは、あるランタイムでプラグインが何を提供するか、そしてアップグレード・アンインストール・
  バージョン整合の確認方法を知るためです。初回接続は、上の表でリンクされた各ランタイムの
  プラットフォームページにあります。
- **制約：**
  - 初回インストール手順を繰り返さない。対応するプラットフォームページにリンクする。
  - Claude Code と Codex の機能を正確に述べる。両者とも 3 つのレビュアー（提案・課題・コード）を
    すべて備える。`userConfig` のトグル面を公開するのは Claude Code だけであり、Codex ではそれらの
    挙動はスキルとフックが直接制御する。OpenClaw、Kiro、Pi を主要ランタイムと同等であるかのように
    示してはならない。
  - プラグインとスキルのバージョンは、Chorus アプリケーションバージョンを追随する単一の番号である。
    個別のスキルインストールを説明しない。
- **参照元：** Claude Code と Codex のプラグインマニフェスト、およびフックとスキルの分担の説明は、
  [Chorus リポジトリ](https://github.com/Chorus-AIDLC/Chorus)にあります。
